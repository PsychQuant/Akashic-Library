# 2026-09-28 兩批 R1 驗證的修正（#669、#670、#586、#572）

兩批 cluster 驗證，每批 6 席齊（4 個 Claude lens、devil's advocate、Codex 跨模型），都沒有 HIGH：

- **C1**：#667–#670
- **C3**：#572、#586、#659

這一輪修掉會誤導使用者的 MEDIUM、兩項 LOW，以及幾處過期的註解。

## C1（#669、#670）

- **重複 venue key 的 error 指錯了出路**（Codex，MEDIUM）。訊息原本把「走 resolve-divergence 合併」列成與改 key 並列的出路，而合併正被同一個 error 擋住（`assertNoCrossRecordErrors`）。改成有順序的兩步：先在 YAML 改掉其中一筆的 key；若兩筆其實是同一本刊，改完之後再合併。`zero-instance-guards` 第 42 列的觸發條件同一句一併改掉。
- **`enrich` 的 doc 說 `writeFailed` 永遠完整**（Codex，MEDIUM）。自 #669 起它以消毒後的 citekey 為鍵，兩筆截斷或逃脫後相同時只列一筆。doc 改成寫明這個例外。
- **CLI help 沒提到 venue／organization key 重複也會被拒**（requirements 與 DA，MEDIUM）。補了四處，都用 `UnlocatableReason` 的常數，與既有寫法一致：
  - `resolve-venues` 的 abstract 與 `--undecided`
  - `update-venue` 的 abstract
  - `resolve-organizations` 的 `--undecided` 與 `--judge`
- **`uniqueKeysWithValues` 的源碼掃描有盲區**（logic 與 DA，LOW）。它原本只找 `$0.key`／`$0.citekey`／`displaySafe` 三種字面，掃不到三種寫法，而本 repo 三種都在用：
  - 具名 closure 參數
  - KeyPath
  - 超過三行的多行寫法

  改成白名單：每個呼叫點都要在前四行內寫一句 `unique-keys: <理由>`。現存的五處逐一查過並標上理由：
  - GraphView 的節點 id 取自以 id 為鍵的字典
  - resolve-people 的 ref 由生成器發
  - ClassicalSemantics 的兩處：atom 在上游已驗過或去重
  - 快照的 raw path 來自目錄列舉

  守衛只驗那句話在不在、不驗理由對不對，這是 `zero-instance-guards` 第 7 列的形。

## C3（#586、#572）

- **`dismiss-divergence` 實跑改為過目標 store 確認閘**（Codex，MEDIUM）。
  - 原本不閘的理由是「以 UUID 定位，指錯 store 只會找不到那筆記錄」，而這個前提是假的：歧異記錄的 UUID 由候選 key 決定（`DeterministicUUID.forDivergence`）。clone、備份，或兩個各自記下同一組候選的 store，同一筆記錄的 UUID 都相同。
  - 這正是 #580 裁決的形狀：錯的 store 上 id 照樣對得上。這個不閘是 #586 實作時代裁的，不是使用者的裁決，所以依 #580 改。
  - #658 的 changelog 已經把這一格記為「在 #298 的事故形狀下不完全成立」。
  - 乾跑不閘，MCP 面不閘。
  - 同步修改的地方：
    - 裁決表：過閘 17、不閘 17
    - `mcp-cli-parity` 那一列
    - `zero-instance-guards` 第 37 列的量測
    - README
- **刪除前只列舉 `entities/` 一次**（security 與 DA）。`assertRecordsRecoverable` 改成回傳它驗過的 id → 路徑，`dismissDivergence` 直接用那一份。先前刪檔前又列舉一次，兩次之間檔案可以被換掉。
- **組合式 warning 的出路點名命令**（requirements，MEDIUM）。「歧異記錄的 shape 沒有合併管線」原本寫「移除面見 #586」，使用者照著走會去讀 issue 而不是跑命令。改成直接點名 `dismiss-divergence <id> --reason …`，涵蓋 StoreHealth 的訊息、它的 doc 與 App 側欄的 help。
- **#572 過期的註解**（requirements 與 regression，LOW）：
  - `assertKeyEdgesAreUnique` 與 `assertPairingHasOneEdge` 的 doc
  - `VenueNameInvariantTests` 的一句
  - `VenueEdgeRemoval` 的 doc 說「由大到小處理」，實作是一次以 index 集合過濾

## #711：`measured-numbers-audit` 的超線性與上限（評審第 0、2、4、5、7 列，MEDIUM）

| 路徑 | 形狀 | 修法 |
|---|---|---|
| `cmdInline` 正規式 `` `[^`\n]*TOOL[^`\n]*RUNNABLE[^`\n]*` `` | 一個沒收尾的反引號後接一長串「工具名＋runnable 字元」，三段 `[^`\n]*` 互相回溯（約 n^2.4） | `measuredNumbersInlineCmd`：一行以反引號切段，相鄰兩個反引號之間的每一段只找一次工具名、再找一次 runnable 字元。答案與正規式相同（三段都不跨反引號與換行；工具名彼此不互為子字串，最左邊的就是最早結束的），後設檢查逐一比對 13 個樣例 |

| 每個裸數字各 trim 一次整行 | 同上，N 乘上行長 | 顯示用的那一段每行至多 trim 一次 |
| 沒有任何上限 | — | 每份檔沿用 `selfProofMaxFileBytes`（4 MiB）、每一行沿用 `selfProofMaxBlockBytes`（128 KiB）——這支的單位是一行，`selfProofMaxBlockLines` 對它沒有意義。超過即具名紅、不判讀那一塊、不截斷。值不另立：同一組常數，改一處兩支一起動 |

## #711：散文的跨段落接續是二次方、不受上限約束（評審第 3、7 列，MEDIUM）

`selfProofIssues` 的 `pendingProse`：上一個段落最後一個邏輯行接上下一個段落的第一個，接起來的單位又被存回去，所以 N 個以 `|` 結尾的段落是一條鏈，
每接一段都把整串重接、重問一次「是否以接續運算子結尾」。每一段都在段落的上限之下，三道上限一道都沒觸發。

- 鏈改成 `ProseChain`：各段收在 `parts`、判讀時才接成一個字串，接續的判讀以 `SelfProofContinuation` 增量地維護（b37 對相鄰 inline code 的同一個做法）。
- 鏈不停：shell 對 `|` 之後的空白行照接，偏向合併（R4）。在第一次接上就停的做法會讓「binary 在第一段、計數在第三段」的單位漏掉。
- 鏈套 fence 與段落的上限（1,500 行、128 KiB），超過即具名紅、不判讀，鏈從下一個段落重新開始。b37 的註解「跨段落的接續至多接兩個段落」改掉。
- 第一版在合併時先 `var c = p` 再 append，存著的那一份仍參照同一塊陣列，每次 append 都複製整串——後設檢查量到 0.05 → 1.82 秒（10 倍輸入 36 倍時間）。
  改成先放掉存著的那一份再 append。

## #711：`--library` 在原文上找（評審第 1、25 列，MEDIUM／LOW）

`<參數>` 先照 shell 拆字、去掉雙引號（`selfProofShellWords`），再找選項（`selfProofLibraryArguments`）：

| 寫法 | b37 | b39 |
|---|---|---|
| `"--library" "$STORE/sub"`、`--"library" "$STORE/sub"`（配 `test -f "$STORE/store.yaml"`） | 認不出、唯讀命令整條豁免 | 認出，`test -f` 驗的不是它的引數 → 紅 |
| `"--library=$STORE/sub"` | 認出（lookbehind 放過雙引號） | 同 |
| `"--library $STORE"`（一個字）、`--note "x --library $STORE"`、`./--library "$STORE"` | 當成有 `--library` | 含 `--library` 卻不是那個選項 → 紅 |
| `-- --library "$STORE"` | 當成有 | 寫在 `--` 之後、是位置參數 → 紅 |
| `--library= "$STORE"` | 認不出、唯讀命令放行 | 沒有值 → 紅 |
| `--library-id 3` | — | 別的選項，照放（`--library-` 開頭的不算形似字） |
| `--library "$STORE" validate`（選項寫在子命令前面） | 認出、`test -f` 滿足就放行 | 子命令要寫在最前面 → 紅（實際是 `Unknown option '--library'`，子命令也認不出來，「會不會寫 store」判不了） |

ArgumentParser 對前五種的實際行為在掃描副本上逐一跑過（`Unknown option '--library /…'`、`2 unexpected arguments`、`Missing value for '--library'`），
引號包起來的選項名照常是那個選項。**仍看不出來的**：`--libr`、`--library-path` 這類認不得的選項讓 ArgumentParser 報錯、計數照印 `0`——守衛不判讀
選項名，規則的「管不到的」補了這一句。

## #711：`.readOnly` 被當成「唯讀」（評審第 6、13、26 列，MEDIUM／LOW）

選擇：**收窄**，不只改名。理由：

- `.readOnly` 在 `WriteGateRulings` 的意思是「不開 store 的寫入閘」。44 格裡有改 registry 的 `file use`／`remove`、寫呼叫端指定的檔的 `export-bib`、
  `export-tables`、`web-read landing`／`check`、`crossref-match`、`abstracts-to-proposals`、`fulltext take`，開瀏覽器的 `fulltext fetch`，連網的 8 個 `s2` 查詢。
  只改名讓守衛的訊息說真話，卻仍放行「照抄重跑會改到 store 以外的東西」的量測。
- 「會不會寫 store」仍只讀那張表（`no-compat-fallback`）。「量測可以用」是另一件事——不寫 store 之外還要只讀、只印——另列封閉清單
  `selfProofMeasurementCommands`（24 格，每格一行理由），每一格都要是 `.readOnly`（另查，那張表改判時這裡的放行跟著失效）。清單外的 `.readOnly` 命令
  帶不帶 `--library` 都紅，訊息說「放行由人加」——與 `selfProofDisplayFilters` 同一個形狀（使用者 2026-10-05 裁決：偏向假紅）。
- 名字的字元類補上數字（`[a-z0-9][a-z0-9 -]*`），44 格全抽到；另查抽到的格數等於不限字元類的格數，抽取再漏格時守衛紅（反向編輯驗過：退回 `[a-z]` 時
  守衛報「命令層有 44 格，只抽到 35 格」，並報 `s2 status` 不是 `.readOnly`）。`s2 status` 在清單裡，量測用它不必帶它不收的 `--library`。
- 讀不到那張表時的退路不變（每一條 `akashic` 的量測都要 `--library`）；那是第 100 列待使用者裁決的那一項，本輪不動。

現有 44 條量測用的子命令只有 `validate`（在清單裡）與 `doctor`、`enrich`、`add-venue`（會寫 store，都帶 `--library` 與 `test -f`），沒有新的紅。

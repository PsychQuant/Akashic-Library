## #711：模板是封閉的，「哪些文字是一個單位」不是（評審第 0、2–7 列，MEDIUM）

R2 把量測收成一個模板（`LC_ALL=C grep -a -q '<片段>' <BIN> && <BIN> <參數> 2>&1 | grep -c '<樣式>'`），並在規則檔、守衛的 doc 與 changelog
寫「封閉的模板沒有旁路可找」。模板確實封閉，但守衛只對它**認得出的單位**求值，而 R2 的單位是「fence 內一個實體行」與「fence 外同一實體行裡的
一段 inline code」。評審在 scratch 副本上重現，下列寫法全部 rc=0、量測條數不變——那條量測根本不成單位：

| 寫法 | 誰找到 | R2 |
|---|---|---|
| binary 在第一行、`\` 接續、`\| grep -c` 在第二行 | 第 3、4、5 列 | 兩行各只有一半，不判 |
| 行尾 `\|`、`&&` 換行 | 第 4、5 列 | 同上 |
| 4 空格縮排的程式碼區塊、`<pre>` | 第 2、4、5、11 列 | 既不是 fence 也不是 inline code |
| 引用區塊裡的 fence（每行 `> ` 開頭） | 第 2、4、5、11 列 | 首字是 `>`，不認成 fence |
| 跨兩行的一段 inline code | 第 2、5 列 | `` `([^`\n]+)` `` 逐行配對，兩半都不成單位 |
| `grep '-c' …`（選項加引號）、`grep -e 'a\|b' -c`、`grep 'x\\|y' -c`（`-c` 在含 `\|` 的樣式之後） | 第 0、6 列 | 計數的 regex 要求選項緊跟空白、不跨 `\|;&` |
| `uniq -c` | 第 11 列 | 不認 |
| `${AKASHIC_BIN:-akashic}` | 第 7 列 | binary 的 lookbehind 排除 `-` |
| 同一行前面一個孤立的反引號、或一段雙反引號 span | 第 19 列 | 配對錯位，後面的量測落在兩段之間 |
| `$'\' # '` 之後接 `\| grep -c` | 第 15 列 | R2 的註解詞法器不認 `$'…'`，把後半當註解，shell 照跑 |
| 33／34 條改寫成預設值展開 | 第 7 列 | 閘全部消失、標題列「1 條」、rc=0 |

### 辨識寬、判定窄

`zero-instance-rows-audit` 的 `selfProofIssues` 改寫：

1. **一個單位裡提到 binary 又有任何形式的計數，就是一條量測**（`selfProofIsMeasurement`）。
   - binary：裸名、路徑、`$(command -v …)`；預設值展開 `${X:-akashic}`、`${X:=akashic}` 也算。`che-akashic`、`~/.akashic`、`akashic-mcp`
     照舊不算。
   - 計數：`grep`／`egrep`／`fgrep`／`rg`／`ag`／`ack`／`uniq` 之後**任何位置**出現 `-c`（併在選項串裡也算）、`--count` 或它的唯一縮寫，
     前後可以有引號；任何 `wc`；`jq` 之後的 `length`。
2. **量測只有一種合法形**：fence 裡的一行、或不跨行的一段 inline code，逐字是模板。其餘一律紅、具名那一行：
   - fence 裡先把 `\`、行尾 `|`／`||`／`&&`／`|&`（其後有 `#` 註解也算）、下一行開頭的 `|`／`&&` 接成**邏輯行**。**跨行的量測一律紅**，
     即使接起來逐字是模板——「一行」是模板的一部分（R2 的「閘在上一行、以 `\` 接續」那一格因此訊息改成「跨 2 行」）。
   - fence 外以**段落**為單位、照 **CommonMark** 配對 inline code（一串 n 個反引號到下一串恰好 n 個；找不到收尾的那串是字面）。跨行的 span 是
     一段（跨行，紅）；只隔空白、以接續運算子相連的兩段接成一個（跨行，紅）。表格一列一段，所以一列裡的孤立反引號不會牽動下一列。
   - fence 與 inline code **以外**的文字（縮排區塊、`<pre>`、散文，去掉 HTML 標記與實體之後）也接成邏輯行判；那裡的量測一律紅：
     「量測只收 fence 裡的一行或一段 inline code」。
   - 每一行先剝掉引用區塊的 `>` 前綴，之後才判 fence——引用區塊裡的 fence 照一般 fence 判。
3. **不再切註解**（評審第 15 列）：R2 的 `selfProofSplitComment` 是一個小型 shell 詞法器，刪掉。辨識看含註解的原文（註解裡提到 binary 與計數
   也算一條量測——誤報的方向），模板自己以 `(?:[ \t]+#.*)?$` 收行尾註解。
4. **`<參數>` 收窄**：不含 `#`（`… validate # x 2>&1 | grep -c 'y'` 的計數整段在註解裡，R2 的模板收它）與單引號（引號能跨過
   `2>&1 | grep -c`），雙引號要成對。

規則檔現有的 35 條量測與整合中的第 85、86 列（Python heredoc，#564）都照舊合格（後者以整合樹的規則檔加上棘輪標記實跑：86 列、34 條、rc=0）。

### 認不出來、所以不紅的寫法（封閉列舉，三類）

規則檔第 19 列的量測段與 `selfProofIssues` 的 doc 是同一份：

1. **不提到 binary 名的計數**——binary 的輸出先存進變數或檔案、另一行再數（第 71 列的補記區塊；變數裝 binary 的路徑再以 `"$AK"` 執行）。
2. **不經 `grep`／`rg`／`ag`／`ack`／`uniq`／`wc`／`jq` 的計數**——`awk` 自己加總、`python3` 數、`sed -n '$='`。
3. **binary 名與計數不在同一個邏輯行**——辨識以邏輯行為單位、不以整個 fence 為單位；後者會把「一行跑 binary、下一行數別的檔」（第 51 列）
   也判成量測。

這三類由下面的棘輪兜底。

### 棘輪：條數的地板與退場區塊的個數（評審第 7、20 列）

規則檔第 19 列的量測段多一行（HTML 註解，GitHub 上不顯示）：

```text
<!-- zero-instance-rows-audit 棘輪：合模板的量測至少 35 條、已退場區塊 1 個 -->
```

- **合模板的量測少於下限 → 紅**：「量測被拿掉、或改成守衛不判讀的寫法」。這是一個不靠辨識的地板——R2 之前唯一的地板是「一條都沒掃到」。
  下限只在新增量測後由人調高；不調只是擋不住**少量**的流失，擋得住整批。
- **退場區塊的個數 ≠ 標記 → 紅**（評審第 20 列）：退場標記讓整個 `text` fence 不被掃，是一個全域的開關；多一個就是多一處量測可以不帶閘。
- **標記不是恰好一個 → 紅**。
- 標題列印出量測條數、合模板的條數、下限、退場區塊個數與它們不掃的行數，例如
  `量測指令 35 條數 binary 輸出（合模板 35 條，棘輪下限 35）；已退場區塊 1 個、共 5 行不掃`。

R2 changelog〈已知的限制〉那句「靜默跳過的那一類只剩上面兩條，所以沒有另加棘輪」已加更正註記（前提不成立）。

## #712：呼叫點測試比（呼叫點, 值）的配對（評審第 1 列，MEDIUM）

`testWriteLegsPassReportingSuppressedFalse` 先前只收引數文字、比排序過的值集合——兩個呼叫點的引數對調仍綠（值的多重集合不變），而對調的後果是
主路徑不再為列表組 `suppressed`。改成收「檔名：`let` 綁定的名字 → 值」：

```text
AkashicService.swift：listing → false
AkashicService.swift：report → (apply ?? []).isEmpty && (reject ?? []).isEmpty
```

不是 `let <名字> =` 形狀的呼叫點記成「未命名」，與任何期望都對不上（fail-closed）。另加一個行為測試
`VenueSuppressedByNormalizationTests.testListingWithEmptyApplyAndRejectArraysStillReportsSuppressed`：apply／reject 為 `nil` 或空陣列的四種組合
都是列表腿、都報 `suppressed`（對調的後果只在列表的輸出看得到：組合腿兩者都非空，對調前後都是 false）。

**負控**：把 `AkashicService.swift` 兩個呼叫點的引數對調、重編——源碼掃描紅，`VenueSuppressedByNormalizationTests` 的三個列表測試
（含新的）紅；以反向編輯還原，與事先存下的副本逐位元組相同。

### 評審第 10 列（LOW）：「同一個拼法」用 canonical equivalence——留給使用者

`VenueResolver` 判「逐字相等的普通已否決」用 Swift `==`（canonical equivalence），所以只差 NFC／NFD 的候選與否決被當成同一個拼法：那條邊
既不在 `candidates` 也不在 `suppressed`（評審以手改 YAML 造出）。改成位元組比較的話，NFC／NFD 變體會出現在 `suppressed` 並帶 `rejectedLiterals`，
`RejectedSpellings.spellings`、`shown` 的排序與 `testCanonicallyEqualSpellingIsNotANarrowing` 要一起改。本輪**不改行為**，列為使用者的決定事項。

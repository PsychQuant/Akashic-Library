# 第五輪：我宣稱「恢復舊行為」的那句話只對一半的輸入成立

2026-08-26。第五輪 verify 3/3 席回報 FINDINGS。**base rate 變成 5/5**——每一輪都在

## ① 兩態壓縮：一個我自己引入的資料遺失回歸

R4 我寫下「兩個方向都跟隨上游」，論證是「這是**恢復**提升進結構化欄位之前的行為」。

那句話**只對解析得出來的單值成立**，而我把它當成全稱命題用。狀態其實有三個：

| 上游 | 正確 | R4 做的 |
|---|---|---|
| 沒給 | 清空 | 清空 ✅ |
| 給了且讀得懂 | 取代 | 取代 ✅ |
| **給了但讀不懂** | **保留既有** | **清空** ❌ |

第三格在 Zotero 上是常態：**它把多個 ISBN 塞在同一個字串裡**，而 `ISBN.init` 對它
必然回 nil。實測受害者 2 筆（`dweck2000social` 精裝／平裝、`kelley2023sample`），
兩者的號都是 `migrate-identifiers` 剛從 Zotero 多 token 字串拆出來的。

**修法不只是「把資料保住」**：多值欄位走 migration 既有的 tokenizer，所以兩個真的號
讀得出來、跟隨語意對它們也成立。吸不吸收按欄位種類，裁決連同量測住在
`absorbsMultipleValues` 的 doc（**DOI 刻意不吸收**——吸收附錄的 DOI 等於一句假的
身分宣稱）。引用它不複製。

### 這個錯誤的形狀值得單獨記

我對這條修復的自我描述非常詳細——changelog 裡還特地寫了「本輪 4 個修復裡，那是唯一
拆掉既有回報通道的一個」。**詳細描述了它做什麼，卻沒問「解析失敗時會怎樣」。**

一句「這是恢復舊行為」聽起來像在引用既成事實，所以它逃過了本來該有的懷疑。
而它是一個**全稱命題**，只被一半的輸入支持。

## ②④ 守衛對自己的涵蓋率說謊——而只有反向負控問得出來

R4 補的跨三面守衛寫 `let identifiers = ["doi", "pmid", "isbn"]`。它的 doc 寫
「**每個欄位 × 每個面**」，`perSurfaceExempt` 列了四個欄位名附理由——讀起來完全像
涵蓋全部。而那四個名字**與那三個交集為空**，一列都不曾生效。

同一個檔案裡的姊妹測試從一開始就走 `Mirror` 反射。**我補上 surface 維度時，
把 field 維度退化成寫死** ——修一個維度、弄壞另一個。

換成反射後它**立刻紅**，抓到一個真缺口：**MCP 顯示 `Entry.provenance`、CLI 不顯示**
——而 CLI 那個檔案上方就寫著「JSON 面有的，人可讀面也要看得到」。

### 反向負控是這一輪學到的東西

| 負控 | 結果 |
|---|---|
| 移除 CLI 剛補的那段 | 轉紅 ✅ 守衛真的在查 |
| **把反射換回寫死清單** | **仍然全綠** ✅ |

第二個是關鍵：它證明**舊版在結構上不可能抓到那個缺口**，儘管缺口是真的、就在那裡。

**一個守衛能不能抓到東西，跟它宣稱自己在查什麼，是兩件獨立的事。** 而只有反向負控
（「把它換成較弱的版本，會不會有差」）問得出這一點——正向負控（「破壞被查的東西，
會不會紅」）對兩個版本都會過。

R4 的 changelog 才剛把「守衛在正向上是空的」列為第 7 種失效模式。這是第 8 種：
**守衛不是空的，但它的涵蓋面比它宣稱的窄**，而正向負控看不出差別。

## 附帶：豁免與已知缺口分開

`exempt` 說「刻意不輸出」，`knownGaps` 說「該輸出而還沒輸出」。混在一起會讓待辦
看起來像已裁決。姊妹測試早就這樣分，本測試補上。

## ③ 一條 TDD 節奏相反的修復——測試一寫就綠

finding 說 `fieldsRemovedByPull` 對識別碼的回報「**正向零覆蓋**」：把
`ZoteroImporter` 的 `identifiersBefore`／`identifiersAfter` 整段刪掉，全套仍然全綠。
實測 `grep -rn 'XCTAssert.*fieldsRemovedByPull' Tests/` → **0**。

補的測試**一寫就綠**——那不是失敗：finding 說的是「零**覆蓋**」不是「壞掉」。
程式碼本來就對，缺的是有沒有東西在看著它。

**所以這裡決定性的檢查是負控而不是 RED。** RED-first 驗的是「測試抓得到缺陷」；
當缺陷是「沒有測試」本身時，能證明的只有負控——刪掉回報迴圈，現在轉紅（舊狀態是 0）。

守衛的**存在**、守衛的**涵蓋面**、守衛**抓不抓得到東西**，是三件要分別驗的事。

## ⑤ 一條永遠到不了退場條件的退場量測

`no-compat-fallback` 要求相容路徑附「回 0 就可刪」的可執行量測。doc 給的是：

```bash
grep -A5 -E '^(issn|isbn):' ~/.akashic/entities/*.yaml | grep -cE '^\S*-- [^v]'
```

`-A5` 的 context 行用 `-` 當分隔（`檔名-<行>`），而編碼器把 `references:` 排在
`isbn:`／`issn:` 之後，於是每個帶 reference 的記錄貢獻一個
`- field: resolution-confirmed` 假陽性。

**在乾淨的 store 上它回 35 而非 0**——退場條件永遠不成立，維護者每次來看都是
「還有 35 筆」，這條路徑會被永久留著。**那條規則存在的目的被它自己的量測擋掉。**

換成逐檔重置狀態的 awk。實測：序列元素 **88 個、裸純量 0 個** → 回 0；
注入一個裸純量 → 回 1。**退場條件此刻其實已經成立了**（刻意不在同一個變更裡刪：
它是 #394 apply 路徑正在用的東西，而那條路徑還沒 merge）。

一條規則要求「附上可執行的量測」時，**那個量測本身也需要負控**——否則它只是一句
看起來很嚴謹的話。

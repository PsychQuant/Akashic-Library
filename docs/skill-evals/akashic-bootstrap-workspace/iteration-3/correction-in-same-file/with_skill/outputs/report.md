## 先說結論：這份檔案裡藏著一筆「更正啟事」

第 4 列標題是 `Adaptive Designs for Dose-Finding in Early Phase Oncology Trials (vol 44, pg 210, 2025)`——`(vol 44, pg 210, 2025)` 是 WoS 標準的更正啟事（correction/erratum）標題後綴格式，指向第 2 列同一篇論文。也就是說：

- 第 2 列＝原始記錄（有錯）
- 第 4 列＝更正啟事，重新刊出正確的作者陣容

這一組正是 skill 條列的「3e：同一份來源檔的其他列」情境——答案已經在檔案裡，只是要往下讀。以下清單已套用這個更正。

## 有問題的地方

### `Wang, Shu-, I` 的名字寫法無法從這份檔案內部解出來，且更正啟事沒有修到它

第 2 位作者的短欄與全名欄本身就對不上：

- 短欄（兩列皆同）：`Wang, SM` → 縮寫是 **S、M** 兩個字母
- 全名欄（兩列皆同）：`Wang, Shu-, I` → 如果照字面唸，縮寫應該是 **S、I**，跟短欄對不起來；而且 `Shu-, I` 這個寫法本身也不像任何常見的中文姓名羅馬拼音（多了一個逗號，把本該連在一起的拼音切開了）

關鍵是：**這處矛盾在原始記錄（列2）與更正啟事（列4）裡寫法完全相同**——也就是更正啟事只修了第三作者（`Ablm`→`Tsai`），沒有連帶修到這個問題。這排除了「用更正啟事回頭校正」這條路（3e 在這裡用不上），因為錯誤本身沒有被更正過。

**我不打算用相似度猜一個版本填進去**（例如猜「Shu-Min」，因為它跟短欄 `SM` 的字母對得上），因為 skill 的紀律很明確：「一筆錯的資料比一個缺的資料糟得多」，而且這裡沒有第二條獨立路徑可以交叉驗證（同一份檔案只有這兩列都帶著同樣的矛盾，不構成兩個獨立來源）。

**建議處理方式**：
1. 姓氏 `Wang` 本身沒有疑義，可以先用它做粗略歸戶，但**名字先留白或標記待確認**，不要用 `Shu-, I` 或任何猜測版本寫入 `names`。
2. 若要解，需要跳出這份檔案走 skill 步驟 2 的外部查證（ORCID、期刊網站上該篇文章的作者頁、或機構名冊）——**這次任務裡我嘗試了一次 WebSearch 想核對這兩篇文獻是否為可查證的真實文獻，但 WebSearch 工具本身回傳設定錯誤（`output_config.effort` 不相容），沒有拿到任何外部查詢結果**，所以這條路目前技術上走不通，只能誠實回報而非假裝查過。
3. 若這兩篇文獻本身就是測試用的合成資料（標題／期刊／年份的組合在文獻資料庫查不到很正常），那麼「無法外部驗證」是預期結果，不代表流程有缺陷；但也代表 `Wang` 這個作者的名字寫法目前**只能標成待人工判定**，不能升級為「高確定度」。

# 寫下一句可能是錯的話之前，先回答四個問題

適用於**會被別人讀來行動的交付物**：issue 的 Expected／Actual、診斷與分析報告、規則與規格、closing summary，以及本 plugin 各 skill 產出的判定與報告。

不適用於**不交付的推敲**。判準是「**會不會被別人讀來行動**」，不是載體種類。

## 為什麼是問題不是分類法

這條規則的前兩版都是分類法（把句子歸類，再依類別決定受不受管）。兩版都被跨模型審查打掉，而且是同一個原因：**每一條分類邊界本身都是一個關於命題世界的斷言**，於是規則的斷言表面比它要管的東西還大。第二版的分類法連它自己舉的例子都歸錯（見下方「這份文件犯過的錯」）。

**下面四個問題不要求你先把句子歸類。** 但要誠實說清楚它們**不是**什麼：第 1 題仍然是一個分類器，而且它的分類結果**直接決定是否完全豁免**後三題。差別只在它問的是**你自己**能不能想出這句話錯掉的樣子，而不是要你認定它屬於哪個預先定義的範疇。

**這個差別能減少什麼、不能減少什麼**：分不出來時預設「可能錯」，所以**模糊**邊界的代價只是多回答三個問題。但它擋不住**你很有把握而你錯了**——第二版正是栽在這裡（把「`VenueType` 封閉三值」當成不可能錯的例子，實測六值）。第 1 題不是保險，它只是把賭注押在「你能不能想像自己是錯的」上。

**先讀第 5 節再用第 4 題的出路**——限定詞不是萬用鑰匙。

## 四個問題

### 1. 這句話有沒有可能是錯的？

有可能 → 往下走。不可能 → 本清單不管它。

「不可能錯」的典型是**規定用語**（「本檔所稱 X 指……」）與**正在做出的決定**（「我們選 A 不選 B」——這句話本身就是那個選擇，它不描述任何事）。

**但這兩類的旁邊各站著一個長得極像、卻可能是錯的鄰居**：

| 不可能錯 | 可能錯的鄰居 |
|---|---|
| 「我們選 A 不選 B」（此刻做出選擇） | 「我們**已經**決定用 A」（報告某個決定存在——那個決定可能根本沒作成，或作成的是別的） |
| 「本檔所稱 X 指……」（規定） | 「`VenueType` 是封閉三值」（讀起來像約定，實則描述現況——實測**六值**，一條 `grep` 就否證） |

判準是：**這句話是在「做」還是在「報」？** 報就可能錯。**分不清就當成有可能錯**，成本只是多回答三個問題。

### 2. 我憑什麼說它？

寫出證據**是什麼**、**怎麼取得的**、**什麼時候**。

- 能用指令取得 → 附指令。但**指令是程序不是證據**：跨網路的查詢明天會給不同答案，所以同時寫下**當次觀察到什麼、哪一天**。
- 證據不是指令能取得的（人的裁定、印刷文獻、需要綜合判斷的身分歸屬）→ 寫出證據**來源**與**取得方式**。身分與歸屬的判定另有規定：見下方第 5 節。
- **取不到證據** → 走第 4 題。

**還要問一次工具本身：它分得清「沒有」與「讀不到」嗎？** 本 plugin 出過一個實例：`literal-census.sh` 把「讀不到 `store.yaml`」與「檔案裡沒有 format 標記」都折成 `0`，於是報告印出「store format 0」——而 store 從來沒有 format 0。**儀器造假時，四個問題全部誠實回答仍然沒用**，因為你量到的就是假的。

**這個實例的修復史，本身就是本題的第二課。** 第一次修：把狀態分開——而兩個標籤寫反了（缺檔與無標記對調），讀一次讀端就能查證。第二次修：對照讀端改對標籤——而註解裡新寫的「對照讀端」仍是**宣稱**，跨模型審查實測出六種輸入形狀分歧，其中三種讓一個讀端整體拒開的 store 被報成健康。第三次才把那句話變成可重跑的東西：`scripts/tests/store-marker-parity.sh` 拿真的 CLI 當 oracle 跑 fixture 矩陣，`scripts/tests/marker-parity-mutations.py` 證明那張矩陣真的會紅。

**兩次「已修」都是未量測的完成宣告，而它們寫在一份教人量測的規則裡。** 對照第 4 題的硬界線：完成宣告正是不得只靠語氣放行的那一類。

#### 附上指令之後，還要問：**它回答的是不是正好這句話？**

#407 R21d–R25h 有**九次**同型失誤（逐次記在下方失敗表），而它們收斂成同一個形狀：
**一個真的查詢，被用來支撐一個那個查詢沒問的性質。**

| 我跑的 | 我寫的 | 差在哪 |
|---|---|---|
| `git log --grep=…` 撈出六個 commit | 「六個都是**更正** commit」 | 查詢問的是「提到該編號」，不是「性質為更正」。實測三個是純新增 |
| 兩個 commit 的時序 | 「每次都**通過了作者當下的檢查**」 | git 證立時序，證立不了「有檢查」或「檢查通過」 |
| `grep -c '一次都沒出現過'` → 3 | 「只有 **1 格**用這個 expect」 | 逐格列出：**3 格全是 `warn_case`**（行 209／246／315）。`grep -c` 的 3 碰巧等於格數，而我推翻它時給了一個沒查的 1 |
| N 行 `run:` 的分類 | 「19 行**單行** `run:`」 | 19 是**總數**，單行 13（且 `13+6+1=20≠19`）。**而 19／13 這兩個數字本身也會過期**——R26b 新增一個 CI 步驟後即變成 20／14，由 `measured-claims-audit.py` 當場抓到。**所以這一列的正解不是記住數字，是每次現查** |
| `git push`（**已啟動、未完成**） | 「三條 CRITICAL 全部已修**並推上各自 branch**」 | **差的是時態,不是內容。** 前四列是「查詢問的不是那個性質」;這一列的查詢問的**正是**那個性質——只是它還沒回答完。實測 `gh api …/commits/<sha>` 回 **422 No commit found**,PR head 仍是上一個 commit。我在 push 的第 10 分鐘寫下完成式,而那個 push 需要 **55 分鐘**（#431:一支測試佔套件 94%）|

**五個都不是假指令，五個都不是假數字。** 錯的是那一步從輸出到句子的擴張——常見的載體是
「也就是說」「因此」「所以」，以及**替查詢結果加上查詢沒問的形容詞**。

**可執行的做法**：把句子拆成「指令回答的部分」與「我補上的部分」，只保留前者；補上的部分
要嘛另外跑一個指令，要嘛明寫「查不出」。R25h 就是這樣收的——六對只有三對查得出時序，
另外三對**寫出「查不出」**而不是算進去。

> **這張表的四列各有現查指令，出貨在 `plugin/tests/measured-claims-audit.py`。**
> 第三列刻意**不計數**——前三次量它時用了三種計數方式（`grep -c`、全格 `re.findall`、
> 逐格解析），得到**三個不同的答案**；現在直接列出行號與函式名。**計數是把多個事實
> 壓成一個數字，而壓縮的方式正是出錯的地方；列舉沒有壓縮。**
>
> **這張表自己也踩過一次**（#407 R25i）：寫完之後逐列現查，第三列一度判成「不成立」
> ——因為驗證腳本數的是**所有** `case`＋`warn_case` 的格（回 3），而該列說的是
> **`warn_case`** 的格（現查為 1）。**同一個形狀，出現在說明它的那段文字的驗證步驟裡。**
> 留著這句是因為它比表格本身更能說明問題：**寫下判準不會讓你免疫，只會讓你下次認得出來。**

### 3. 我手上的東西還說了什麼，是我沒讀的？

這一條是本規則最貴的一課，因為**這份文件在上一版就犯了**：查三筆記錄有沒有頁碼，腳本只印 `page` 欄，於是寫下「能寫的最強結論就到這裡」——而**同一份回應裡有兩筆帶著 `article-number`、兩筆帶著 volume、三筆帶著 issue**——原句問的是「卷期頁碼」，答案本來就在手上（實測見下）。

**投影窄於命題，和結論寬於觀察，是同一枚硬幣。** 取回一份資料之後，先看完它，再決定能寫什麼。

#### 表格是投影，而**維度就是投影方向**

#407 R26f／R26m／R26n 是同一個形狀的三次，而它們都發生在**畫了一張表之後**：

| 輪 | 表列了什麼 | 結論推廣到 | 漏掉的維度／格 |
|---|---|---|---|
| R26f | `--no-verify` × 兩個選項 | 全部情境 | **正常 push**（那格兩者不等價）|
| R26m | 2×2 矩陣 | 「全部四種情境」 | 條件化後只剩 **2 格**，計數就錯 |
| R26n | push 方式 × CI 狀態 | 「正常 push」整體 | **hooksPath 指不指向本樹**（第三維）|

**畫表會讓人覺得已經窮舉。** 但表只窮舉了**你想到的那些維度**——漏掉的那個維度不會在表裡
留下空白，它會讓每一列**看起來都完整**。R26n 的那個維度**就寫在同一份文件上方**（觸發點表
第 1 格：`core.hooksPath` 指向主 repo、對這些守衛 0 命中），我引用過它，然後在下方的表裡
沒有把它當成維度。

**可執行的做法**：寫下「所有／全部／整體」之前，先問**這張表的維度是我選的還是窮舉的**，
再問**有沒有一個條件會讓某一列的答案翻轉**——若有，那就是一個維度，不是一個註腳。

#### 判準只用它的來源案例驗證，等於沒驗證

#407 R26t／R26v 是同一個方法找到的兩個洞，而那個方法值得單獨寫下來：**拿判準去測一個
它沒提到的案例**。

| 輪 | 判準當時的寫法 | 來源案例 | 用**新**案例測出的洞 |
|---|---|---|---|
| R26t | 「兩維度之間有**因果隔離**就可合併」 | `--no-verify` × hooksPath | 該詞有兩種讀法（彼此獨立／對結果無關），而來源案例**同時滿足兩者**所以看不出差異。用另一個案例（push 方式 × CI 狀態）就分岔 |
| R26v | 「一方的值讓另一方**對結果**無關」 | 同上 | 沒說是**哪一欄**的結果。表有兩個結果欄，而「CI 恢復 × hooksPath」**一欄無關、一欄有關** |

**共同形狀**：判準是從案例抽出來的，所以它在那個案例上必然成立——**驗證它需要一個它
沒見過的輸入**。這與負控的邏輯相同（一個從沒紅過的檢查與不存在的檢查長得一樣），只是
對象從程式碼換成了判準。

### 4. 我寫下的範圍，有沒有超出證據的範圍？

- 查了 A、B、C 三個來源都沒有 → 寫「**在 A、B、C，以查詢 Q，於某日查無**」，不寫「沒有」。
- 量了一個實例 → 不寫全稱句。
- 沒查 → 限定詞**寫在句子裡**（「推測」「待查」），並寫出**要查什麼**才能定案。

**但限定詞有一條硬界線：**

> **凡後續行動的正當性依賴這句話為真，就不得只靠限定詞放行。**

要嘛去查，要嘛把那句話移出結論區、明擺成待決。

判準是**依賴關係**，不是行動的種類。刻意不寫成一張封閉的行動清單——上一版寫了三項（寫進 store／決定分母或批次範圍／當成完成宣告），而跨模型審查指出：本規則自己的立案實例就落在那三項之外。「根據一個未查證的『外部 ID』去改一筆 YAML 或一段程式」不必然是「寫進 store」「決定分母」或「宣告完成」，照字面加一個「推測」仍然放行——而那正是實例一造成下游做錯事的路徑。同樣接不住的還有：據此**拒絕**一個候選、**刪**資料、**選**一種修法、**停止**調查、**改**規格。

（那三項仍是好例子，只是它們**是例子不是出口清單**。全域規則 `common-spec-prose-enumeration` 記過這個形狀：總括判準與封閉列舉是兩份不會一起改的規格，而封閉列舉會在邊界上把判準清空。）

兩個立案失敗都是「有能力查卻沒查」，而兩次的傷害都不是語氣造成的，是**建立在那句話上的動作**造成的：加一個「推測」不會阻止任何一條因果鏈。

## 5. 身分與歸屬的判定另有規定

判定「這個 literal 作者就是這個人」「這個刊名就是這個 venue」時，本清單**不重述**該領域的判準——重述會走樣（前一版對兩份規則的就地重述被跨模型審查逐句比出多處失真，型態見下方失真表；**確切數目此處不寫**——那個計數只存在於本 issue 的 verify comment，而讀到本檔的人多數取不到它，寫一個他無法重跑的數字正好違反第 2 題）。

實際規定住在 Akashic repo 的 `.claude/rules/identity-is-judged-not-matched.md`。**該 repo 是 private，沒有存取權的讀者（含未認證的 agent）取不到全文。**

取不到時的出路是**明說取不到**，不是憑印象補上：把「依據該規則的哪一條」寫成待確認，或請有存取權的人補。**不要憑記憶重述一份你讀不到的規範。**

### 一、另一個 private repo 的一張 issue

（**該 repo 與該 issue 刻意不具名**——見本節末的裁決。）

該 issue 的 Expected 假設某筆記錄 `pages` 欄的 16 位數字是「某種外部 ID」，並據此提了兩個修法。**那個假設寫下時沒有查證。**

把該數字當成 DOI 後綴反查，2026-08-21 觀察：

```bash
# --fail 讓 HTTP 錯誤變成非零 exit，|| 讓失敗說出來——否則 5xx 或空回應會被
# 下游解析成「欄位沒有」，而那正是第 2 題要問的那件事（工具分得清「沒有」與
# 「讀不到」嗎）。本檔上一版的兩個範例都沒有這一層。
curl -sS --fail -H 'User-Agent: your-tool (mailto:you@example.com)' \
     https://api.crossref.org/works/10.1177/1948550610386628 \
  | python3 -c "import json,sys; m=json.load(sys.stdin)['message']; \
      print(m.get('DOI'), '|', (m.get('title') or [''])[0][:40], '|', m.get('volume'), m.get('issue'), m.get('page'))" \
  || echo '✗ 請求失敗——這一筆「沒有值」不成立，是沒問到'

```

**為什麼這個 repo 不具名，而它的主題照常出貨（顯式裁決，2026-08-21，R7 修正）**

本 plugin 經由**公開**的 marketplace 發布——證據見下方自我量測表（marketplace repo
的 `isPrivate` 為 `false`，且其 manifest 列出本 plugin）。所以這一節寫下的東西是公開的。

**受保護的是 repo 的存在與名字，不是那張 issue 的主題。**

上一版把裁決寫成「具名會把它的存在與**那張 issue 的主題**一併公開」，然後在同一段
把主題完整出貨（記錄的形狀、唯一識別的 DOI、回傳的標題片段）。**藏掉的是最不敏感
的那一半，保留的是裁決自己指名為敏感的那一半**——一句寫下來卻未被遵守的斷言，
出現在一份以「別寫沒量過的話」為主題的規則裡。

裁決收斂為：

| | 處置 | 理由 |
|---|---|---|
| private repo 的**名字與存在** | 不具名 | 那是該 repo 選擇 private 所保護的東西，而具名不增加任何教學價值 |
| 那次失敗的**形狀與量測** | 照常出貨，含 DOI | 這條規則的旗艦要求就是「量測必須可重跑」。遮蔽 DOI 會讓它自己的範例變成一句不可查證的話——**用違反規則的方式保護規則**。DOI 本身是一篇已發表論文的公開識別碼 |

**Akashic-Library 照常具名（含 issue 編號與主題）**：它的名字**已經**在公開處——
出貨的 `plugin/bin/akashic-mcp-wrapper.sh` 第 6 行逐字寫著 `REPO="PsychQuant/Akashic-Library"`，
任何裝了這個 plugin 的人都讀得到。上一版引的證據是「marketplace entry 與 README」，

這個結論。**結論對，引用的證據不是它**；這正是第 2 題的字面要求。

這是一次裁決，不是副作用——要改請改這一段。

### 二、一份逐列對照報告的一句話

原句：「出版都超過半年了，卷期頁碼照理已經確定。可用 DOI 向出版商查一次補齊」。**「照理已經確定」沒有查證。**

2026-08-21 觀察（**把命題涵蓋的每一件事都印出來**——原句說「卷期頁碼」，所以四欄都要看，這正是第 3 題的教訓）：

```bash
for d in 10.3791/68984 10.1007/s44195-025-00108-7 10.1007/s11009-025-10201-6; do
  curl -sS --fail -H 'User-Agent: your-tool (mailto:you@example.com)' \
       "https://api.crossref.org/works/$d" \
    | python3 -c "import json,sys; m=json.load(sys.stdin)['message']; \
        print('page=', m.get('page'), 'art#=', m.get('article-number'), \
              'vol/iss=', m.get('volume'), '/', m.get('issue'), \
              (m.get('container-title') or [''])[0][:30])" \
    || echo "✗ $d 請求失敗——這一筆不是「沒有頁碼」，是沒問到"
done
# 當次回傳：
#   page= None art#= None vol/iss= None / 223  Journal of Visualized Experiments
#   page= None art#= 23   vol/iss= 36 / 1      Terrestrial, Atmospheric and Ocean
#   page= None art#= 78   vol/iss= 27 / 4      Methodology and Computing in Appli
```

**能寫下的**：當次三筆的 `page` 皆為 None；其中兩筆回傳了 `article-number`（23、78）；**三筆都回傳了 issue，其中兩筆另有 volume**（依序 `vol=None, iss=223`、`vol=36, iss=1`、`vol=27, iss=4`）。
**不能寫下的**：「這些刊物不用頁碼」——那是關於期刊政策的命題，需要期刊自己的投稿格式規格。

**這個實例自己示範了第 3 題三次。** 原句說的是「**卷期**頁碼照理已經確定」，而它涵蓋兩件事。當次回傳能支持的是：三筆有 `issue`、兩筆有 `volume`、三筆的 `page` 皆為 None、其中兩筆有 `article-number`。

**不能寫下的（第四次示範，就在這一段）**：「卷期**已確定**」與「頁碼**不存在**」。前者是關於定案程度的斷言——Crossref 回傳一個值，不等於出版商已定案；後者需要期刊自己的投稿格式規格，正是上一段才剛說過不能寫的那句話。「那兩本用 article number **取代**頁碼」同理：回傳裡有 article-number，不表示它取代了頁碼。

前一版只印 `page` 欄，於是既漏掉 article-number、也漏掉卷期——**對一個講「卷期頁碼」的命題，只量了其中一半，還對那一半下了整句的裁決**。

**第三次是這一段自己。** 補上卷期之後，本檔把它寫成「三筆都回傳了 volume／issue」——而同一句的括號裡就印著第一筆是 `vol=None`。**證據貼在斷言旁邊，仍然沒有被讀。**「都」這個字省掉的正是那個 `None`：三筆有 issue，只有兩筆有 volume。（R4 verify 的 CRITICAL 2；當時全庫測試 2055 綠、九項驗收九項通過，這句話照樣是假的——**測試驗的是程式，不是散文**。）

取回一份資料之後，先確認**你的命題涵蓋幾件事**，再確認**手上的回應回答了其中幾件**。

## 誠實邊界

**擋不住「我以為我查過了」。** 上面兩個失敗都是有能力查卻沒查。

**掛載機制只碰得到 skill 檔，而且「碰得到」比看起來弱。** 本規則由各 skill 的 see-also 引用而生效，所以它實際到得了的是**寫 skill 時**與**跑 skill 時**。

**一個 markdown 連結不等於規則已載入**：它只是一行字，能不能變成行為取決於讀 skill 的那個 agent 有沒有去讀它、以及讀了之後有沒有照做。`plugin/tests/rule-coverage.sh` 驗的是**引用存在且路徑解析得到**——那是必要條件，不是充分條件。真正的載入保證需要別的機制（skill 執行時強制讀入，或撰寫時的 gate）。這一句寫在這裡，是因為「6 個 skill 都引用了」很容易被讀成「6 個 skill 都遵守了」，而那兩件事之間沒有任何東西。而上面兩個立案失敗一個在 GitHub issue 的 Expected、一個在分析報告裡——**兩者都不在 skill 檔內**。這是已知缺口，不是尚未發現的問題：**掛載面比適用面窄**。要真正涵蓋 issue 與報告，需要的是別的機制（撰寫時的 gate 或審查時的檢查），不是這份檔案。

**「曾經為真、因世界改變而變假」——本清單管得到寫下的那一刻，管不到之後。**

這句話要小心讀，因為它很容易被當成豁免用：「我寫的時候是對的」。**它不是豁免**。第 2 題要求寫下**當次觀察到什麼、哪一天**，理由正是這件事：時間戳記存在的意義就是讓後來的讀者知道這句話的保鮮期，而不是讓作者事後說「當時是對的」。沒有時間戳記的陳述**不會**因為「也許當時是對的」而免責。

本清單真正管不到的只有一件事：**它不會回頭去重驗你半年前寫下的那句話**。那需要守衛（會在漂移時變紅的東西），而守衛屬於另一個機制。本 plugin 自己就有一個實例：`.claude-plugin/plugin.json` 的描述寫「Store format 10」，而本機 store 的 `store.yaml` 寫 `format: 12`（單機觀察，未查證該描述寫下時是否正確、也未查兩者是否可相容）。追蹤：Akashic-Library#408。

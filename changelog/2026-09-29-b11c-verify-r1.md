# 2026-09-29 b11c 驗證 R1：#544 的因果句是假的、#614 的閘漏了兩格、#595 的插值沒有編碼（#544、#614、#595）

b11c 三張（#544 `update-entry --remove-field`、#614 `--add-source`、#595 verify-venue 端點插值）落地後的 6 席驗證共 46 則（2 HIGH、
10 MEDIUM、其餘 LOW／INFO）。本輪逐則重讀程式碼確認再修；第 1–40 則的處置見文末表。

## 診斷（根因）

**#544 的兩個 HIGH（第 1、2 則）是同一個錯：把「守衛放在哪」與「那 21 筆從哪進來」混成一件事。** 原 commit 在
`ndjson-abstracts-to-proposals.py` 加了 `crossref-no-metadata`，並在轉換器 docstring、`akashic-venue-works` SKILL、changelog 三處寫
「21 筆 work 就是這樣帶著錯誤頁當摘要進庫的」。兩席各自以 live store 的 git 史（`e3b25a6d`，2026-09-01「#423 階段 A」）與階段 A 匯出檔確認：
那 21 筆是**階段 A**（OpenAlex `abstract_inverted_index` 還原 → `create-entry`）建檔時帶進來的，OpenAlex 回傳的摘要本身就是樣板；
轉換器是 2026-09-07（`d5111c4b`，#516）才新增的階段 B 工具。本輪重跑 `git -C ~/.akashic log -S'This DOI is not currently attached'`
（唯讀）：最早一筆是 `e3b25a6d`，與兩席所述相符。

**#614 的兩個實作缺口**：`sourcePresence` 用 `fileExists(atPath:)`（目錄也回 true）；`addEntrySources` 對空集合仍讀 index，
與文件說的「已連過的是 no-op、不檢查」不符。另外讀取面對 `akashic.sources` 靜默（能寫不能讀）、MCP 的 `sourcesAdded` 無上限。

**#595 的插值只有格式檢查沒有編碼**：DOI 的 `^10\.[0-9]{4,9}/\S+$` 放行所有 URL 結構字元（store 的 2,448 個 DOI 裡有 8 個含 `<`／`>`／`;`），
而它自己宣稱「日後改走 shell，同一份驗證同樣要先做」對 DOI 為假；ISSN 的 `\d` 與同檔 #589 的 ASCII 立場矛盾，也沒說插進路徑的是哪一種形；
新句把 `MCP／WebFetch` 寫成取得管道，違反 `web-access-via-safari-browser`（grandfathered 只讓檔修 bug、不讓它新增同類指令）。

## 改了什麼

### #544

- **三處假的因果句改成量得到的說法**：轉換器 docstring、`akashic-venue-works/SKILL.md`、`2026-09-29-entry-field-removal.md`。守衛保留，
  並寫出它真正的理由：`update-entry --remove-field` 移除那 21 筆的摘要後，它們沒有摘要、會被排回階段 B，那時若抓到同一個樣板，這裡擋得住
  （階段 B 實際會不會抓到，沒有量過）。
- **階段 A 的入口補同一個判準**（`akashic-venue-works` SKILL 階段 A 與匯入序第 2 步）：還原出的摘要以
  `This DOI is not currently attached to any metadata records` 開頭時，不放進 `create-entry` 的 `fields.abstract`，該筆照建、報告的排除計數
  帶略過筆數。字串與轉換器的 `CROSSREF_NO_METADATA` 是同一個，兩處各自註明「改一處要一起改」。
- **核心層不動**（`create-entry`／`enrich`／`validate` 都不過濾）：那牽涉 `lossless-intake` 的封閉列舉，已開 **#676** 交使用者裁決；
  changelog 與 SKILL 都寫明「核心不過濾，見 #676」。
- **已歸戶的 `.key` venue 邊也要出聲**（第 23、35 則）：新增 `venueKeyEdgesFromRemovedValues`——移除後仍掛著的 `.key` 邊，若那個 venue
  上有 `work:<citekey> :: <literal>` 的 confirmed verdict 而 literal（正規化後）就是被移除的值，就列出（邊本身不記出處，出處只在 verdict 上）。
  本面仍不動它們；`venueEdgesNote` 指路：先 `resolve-venues --demote` 再 `--drop-venue`（刪唯一的 key 邊要先 demote）。
- **`reintroductionNote`**（第 7、14 則）：每筆報告都帶，點名三條會把值補回去的路徑——`import-wos` 回填（只多不少）、`enrich`（add-only）、
  Zotero pull。原本只有主來源是 Zotero 的記錄才附 `zoteroNote`（仍保留）。CLI `--remove-field` 的 help 與 MCP 工具描述都講到三條。
- **`apa7RequiredNowMissing`**（第 36 則）：用既有的必要欄位表（`BibExport.apa7Report`，不另立第二份）對移除前後各算一次，只報這次**新增**的
  缺漏（移除前就缺的——例如沒有作者——不是這次造成的）；乾跑也附。`validate` 不報、`export-bib` 才印 ERROR，這是這一則要補的落差。
- **「report-only 取代留記錄」的誠實化**（第 7、14 則）：changelog、`mcp-cli-parity` 的 update_entry 列、`two-kinds-of-edits` 那一列、
  `EntryUpdate.swift` 的檔頭、`docs/store-format.md` 都改成——2026-09-27 的裁決是為 #588／#572／#586 下的，延伸到 `fields` 的值是 Claude 代裁、
  待使用者確認；issue 要的 #450 形記錄沒有做。store format 不動、不加墓碑（那要使用者裁決）。
- **`two-kinds-of-edits` 的逆操作句**（第 22 則）：「`enrich` 補回」只對一般字串鍵成立；`doi`／`pmid`／`isbn` 的殘留與 `enrich` 拒收的鍵
  （`issn`、`type`、`title`、`venues`）以 git 還原。

### #614

  截的只是報告。`mcp-cli-parity` 的列記為有記錄的差異。
- **MCP 缺 `citekey`**（第 42 則）：`akashic_update_entry` 的 `citekey` 缺少或全空白回「citekey 是必填參數」，不再走到服務裡才說「找不到：citekey「」」。

  （第 21 則：原本「只能手改 YAML」與同檔「不得手改條目 YAML」互相矛盾）；exit 5 經人確認的存 `*.unverified.pdf`、note 寫人工確認；

### #595

- **`akashic-verify-venue` 的〈端點插值〉整段重寫**（第 5、8、9、10、12、13、15–19、24、25、34、38、39 則）：
  - **取得一律經 safari-browser**，程序指向 `web-access.md`；拿掉「MCP／WebFetch」；「本 skill 不執行任何 shell 命令」改成有範圍的說法：
    本 skill 自己不定義、也不執行 shell 命令，web-access.md 的程序才會組 safari-browser 命令，插進去的值只能是編碼後的形；檔內的 `git status`、
    `update-venue …`、`akashic venue …`、`akashic doctor`、`migrate-venues` 是指給使用者或呼叫端的命令，本 skill 不代跑、也不把第三方字串插進它們
    （`--remove-issn '<issn>=理由'` 那一行另註：理由含 `'` 時由組命令的人負責引號）。
  - **`<DOI>`**：只取 `akashic_get_entry` 的 `doi`（陣列——零個＝未需要、多個＝逐個查）；不再另立第二份形狀 regex（它比 store 的 `DOI` 型別嚴，
    且放行所有 URL 結構字元），改為：`.`／`..` 路徑段不查；**逐字元 percent-encode，只保留 `A–Z a–z 0–9 - . _ ~ /`**；給兩個含保留字元的例子

  - **`<issn>`**：三種來源（store、API 回應、使用者回覆）並列，後兩種是待判定的證據；只去 ASCII 連字號與空白、`x` 轉 `X`，整串比對
    `[0-9]{7}[0-9X]`（ASCII 數字、fullmatch 而非 `$`）；**插入路徑段的是 `NNNN-NNNN`**。
  - **`<刊名>`**：來源補上建檔腿（literal 不在 candidates 時取自該 entry 的 `fields`）；編碼用 web-access.md 的程序（寫檔再轉碼，不經 shell 引號）。
  - 檔內另兩處「WebFetch 回的是模型改寫稿」改成不再指定管道的說法（頁內 fetch 可存原始位元組，能不能接到 #587 那一格沒有在本 skill 驗過）。
- **`web-access-via-safari-browser` 與 `web-access.md`**：verify-venue 已含指標，從 grandfathered 清單移出（重量：命中 5 個檔、3 個不算、其餘 2 個）；
  第 4 源的瀏覽器契約仍待 #593，該 skill 不抓不讀那一源。

**#595 補的同類**（第 26 則）：`akashic-fetch-fulltext` 第 3 步把第三方的標題放進雙引號的 shell 命令。改成 Write 工具寫進暫存檔、
`--title "$(cat '…')"` 帶入（`$(…)` 的輸出不會被 shell 再展開）；DOI 只取 `doi` 陣列並過 web-access.md 形狀表；`--landing`／`--prime` 的第三方網址、

## 使用者動作（#544 的 Expected 1 仍未完成——本輪沒有碰 live store）

21 筆 abstract 與 `anon2014entry` 的 `journaltitle`、`anon2011entry` 的 `publisher` 要由你跑。2026-09-29 唯讀量測 live store：恰 21 筆的
`fields.abstract` 以樣板開頭，citekey 如下。**每個命令先不帶 `--apply` 看乾跑報告**（`fieldRemovals[].value` 的前段要是那段樣板）。

```zsh

cks=(indicated2002bpsychological indicated2002gpsychological indicated2002hpsychological indicated2002psychological \
     indicated2003bpsychological indicated2003cpsychological indicated2003dpsychological indicated2003epsychological \
     indicated2003fpsychological indicated2003gpsychological indicated2003hpsychological indicated2003ipsychological \
     indicated2003jpsychological indicated2003kpsychological indicated2003new indicated2003psychological \
     indicated2004bnew indicated2004cnew indicated2004dnew indicated2004new indicated2005new)
why='abstract=Crossref 的無 metadata 錯誤頁（This DOI is not currently attached to any metadata records），不是這篇的摘要（#544）'

# 1. 乾跑（預設）：逐筆看報告
for ck in "${cks[@]}"; do akashic update-entry "$ck" --remove-field "$why" --library "$HOME/.akashic"; done

# 2. 確認後實跑：每筆改的是不同的檔，所以中間不必 commit
for ck in "${cks[@]}"; do akashic update-entry "$ck" --remove-field "$why" --library "$HOME/.akashic" --apply || break; done
git -C ~/.akashic add entities
git -C ~/.akashic commit -m "fix: 移除 21 筆 Crossref 無 metadata 錯誤頁當摘要的 abstract——不是這篇的摘要（#544）"

# 3. 兩筆填錯欄位的值：先乾跑；報告的 venueEdgesFromRemovedValues 會印出 literal 邊的位置（citekey:index）
akashic update-entry anon2014entry --library "$HOME/.akashic" \
  --remove-field 'journaltitle=科技部大專生研究計畫是補助計畫名稱，不是期刊（#544）'
akashic update-entry anon2011entry --library "$HOME/.akashic" \
  --remove-field 'publisher=華總一義字第10000015611號是總統令字號，不是出版者（#544）'
# 確認後各加 --apply，然後 commit（下一步的 --drop-venue 也要求 work 檔已 commit）
git -C ~/.akashic add entities
git -C ~/.akashic commit -m "fix: 移除兩筆填錯欄位的值：journaltitle 是補助計畫名、publisher 是總統令字號（#544）"

# 4. 兩條 literal venue 邊：<index> 取自第 3 步報告的 venueEdgesFromRemovedValues
akashic resolve-venues --library "$HOME/.akashic" --drop-venue 'anon2014entry:<index>=補助計畫名稱被記成期刊，欄位已移除（#544）'
akashic resolve-venues --library "$HOME/.akashic" --drop-venue 'anon2011entry:<index>=總統令字號被記成出版者，欄位已移除（#544）'
```

- 第 3 步移除 `journaltitle`／`publisher` 之後，那兩筆的報告可能帶 `apa7RequiredNowMissing`——那是預期後果（那個欄位本來就不是刊名／出版者），
  不是錯；要不要補正確的值是另一件事。
- 移除後 `import-wos` 回填、`enrich`、Zotero pull 都可能把值補回來（報告的 `reintroductionNote`）；這 23 筆的來源是 #423 階段 A 的 OpenAlex 匯出

## 誠實邊界

- **不重新雜湊 blob**（第 27 則）：位置是普通檔、index 有記錄，但位元組是否真雜湊成那個 digest 沒有驗。要補是另一個面。
- **`add-source` 不要求 work 檔已 commit**（第 28 則）：還原程序寫成「實寫之前先 commit store」，是操作者的責任；要把 git 閘接上去是 #677 移除腿的範圍。
- `scanIndex` 現在為每個 digest 保留第一列的字串欄位，`storeSource` 與 `auditSourceIndex` 每次呼叫也付這個成本（第 30 則後半）——live store 約 95 列，量小；
  共用基礎設施的行為擴張，記錄不修。
- `argRequired` 只用在 `akashic_update_entry`；其餘工具仍是 `arg(k) ?? ""`。
- 階段 A 的判準是 SKILL 散文，不是程式：下一次階段 A 的執行者要記得做。核心層要不要偵測是 #676。
- `venueKeyEdgesFromRemovedValues` 靠 venue 上的 confirmed verdict 認出邊的出處；手改出來、沒有 verdict 的 `.key` 邊認不出來。
- 沒有實跑 safari-browser：verify-venue 的取得程序照 web-access.md 的文字，沒有在真實頁面上跑過。

## 代裁（使用者可翻）

1. 把移除面一族的 2026-09-27 裁決延伸到 `fields` 的值（不留記錄）——**沿用原實作的決定，本輪只是誠實化**；使用者若要 #450 形記錄，是一次 store format 變更。
2. verify-venue 移出 grandfathered 清單：新句改成指向 web-access.md 後，量法的最後一段本來就不再列它；第 4 源的瀏覽器契約仍留給 #593。
3. DOI 在 verify-venue 用編碼、不用 web-access.md 形狀表的拒收（表對 `#`／`?` 拒收）——理由與量測寫在 SKILL。
4. `SourcePresence` 把 symlink 也當非普通檔：`sources/` 由本工具寫成普通檔，位置上出現 symlink 就是有人動過；若使用者有意用 symlink 共用 `sources/` 的個別 blob，會被拒。

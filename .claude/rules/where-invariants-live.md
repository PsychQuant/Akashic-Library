# 不變式住在三層，而中間那層與最外層的紀律**相反**

一條不變式可以住在三個地方。**選最左邊那個裝得下它的**：

| 層 | 機制 | 違反時會怎樣 | 這一層的紀律 |
|---|---|---|---|
| **記法** | 型別／schema 讓它**寫不出來** | 編譯不過、decode 拒收 | 首選。能不可表達就不要靠檢查 |
| **守衛** | 測試／`validate` 在執行期檢查 | 紅燈、`.error` | **述性質，不要列範例** |
| **散文** | doc／rule 用文字說 | 沒有東西擋 | **列舉，不要寫總括判準** |

**守衛與散文的紀律是相反的。** 這是本規則存在的全部理由——同一個直覺（「講具體一點」）在散文層是對的、在守衛層是錯的，而它今天一天之內讓同一個缺陷發生四次。

## 為什麼相反

| 層 | 失敗方向 | 為什麼 |
|---|---|---|
| 散文 | **過度延伸** | 判準的**字面**會涵蓋你沒同意的案例，然後有人照著推導 |
| 守衛 | **涵蓋不足** | 範例表在一個**開放空間**裡必然留洞，而洞是一族不是一格 |

散文的解藥是封閉列舉（見 `common-spec-prose-enumeration.md`）。守衛的解藥**正好相反**：把斷言寫成**性質**，不要寫成 pair 的表。

### 實例（2026-08-10，`PsychQuant/Akashic-Library#222`）

要證明 `matchingKey` 不重排語序，第一版釘兩個 pair：

```swift
("Liang, Yu-Jen", "Yu-Jen Liang")     // 全寫形
("Chang, Y-H.",   "Y-H. Chang")       // 縮寫形
```

並在註解寫「**漏掉的那格剛好是唯一能過關的**」。**那句話是假的。** verify 席把 `matchingKey` 逐字重建、掛突變跑全套 1249 測試，找到**三個**存活的語序塌陷：

| 突變 | 條件 | 全套 |
|---|---|---|
| M6 | given 段不含 `-` | 全綠 |
| M7 | family 段是多 token（`van der`、`de la` 這類姓氏的特例分支就長這樣）| 全綠 |
| M8 | family 是漢字 | 全綠 |

M6 讓 `Guan, Yongtao` ↔ `Yongtao Guan` 塌縮——**那是這個 codebase 自己的常用範例**。

原因是範疇錯誤：兩個被釘住的 pair，**除了 M5 所依據的那個屬性之外，其餘每個判別屬性都相同**（單 token family、帶連字號的 given、拉丁、兩 token）。補一格，開三格。

**能封閉的只有性質**：

```swift
XCTAssertEqual(NameNormalization.matchingKey(s).split(separator: " ").map(String.init),
               s.lowercased().split(whereSeparator: \.isWhitespace).map(String.init),
               "matchingKey 不得重排 token：\(s)")
```

一條同時殺掉 M5／M6／M7／M8。

## 記法層優先：能寫不出來，就不要靠檢查

`AuthorizedNames.validate` 的不變式 1 要求 `authorized ⊆ names`。實測 867 筆 person、866 筆有 `authorized`、**零筆矛盾**。

看起來像「不變式活得好好的」。拆開就不是了：

| 形狀 | 筆數 | 子集關係為什麼成立 |
|---|---|---|
| `authorized == names`（逐字相同，含順序）| **730（84%）** | **恆真** —— 兩張清單是同一份，沒有人做過任何選擇 |
| `authorized ⊊ names`（真子集）| 136 | 有人真的挑過（留漢字＋`Given Family`，去掉 `Family, Given` 引用形）|

**零違反不是維護的成果，是 84% 的記錄根本沒行使過這個欄位。** 一個絕大多數情況下恆真的不變式，量不到它自己的鬆脫——而 schema 把 `authorized` 放成 `names` 的兄弟，於是子集關係只能在執行期被檢查（追蹤：`#227`）。

> 這 730 筆同時是 `#222` 那條禁令的實地證據：`authorized` 為空本來是**有意義的狀態**（「還沒指定該怎麼稱呼他」，此時 `displayName` 退回 `key`，讓缺口在輸出上看得見）。機械複製一份 `names` 進去之後，那個狀態在這 730 筆上**已經不可回復**——分不出「沒人決定過」與「決定是全部」。

同一個 repo **自己已經寫下過這條原則**（`Organization.swift` 的 `OrgRef` doc）：

> 不需要「是否已歸戶」的旗標欄位，缺席本身就是資訊。**兩個欄位可以互相矛盾，一個 sum type 不會。**

原則在庫裡，只是沒被套用到每一處。

### 這個 repo 已經做對的地方（記法層的既有前例）

- `Author` / `OrgRef` 的 `.key | .literal` —— 「已歸戶」與「未歸戶」是**和**不是兩個可矛盾的欄位
- `ResolvedStore` —— `GraphModel` 只收它，於是 `GraphModel(store: LibraryStore(root: x))` **編不過**（`.unregistered(store, reason:)` 是刻意留的洞，理由必填）
- `EntityKind.knownLabels` —— 封閉集合，不在其中的裸標籤 quarantine，**不猜**
- `DateRange` —— `end` 與 `endedUnknown` 的矛盾組合、`attested` 與起訖並存，**decode 直接拒收**
- `Proposition`（`Sources/AkashicProposition/Proposition.swift`）—— 封閉代數型別，且它的 doc **自己就把本規則講完了**：

  > **錯誤的 arity 在型別層已不可表達**（enum 的 case 固定帶兩個具名引數），所以這裡只剩型別擋不住的那些。

  「所以這裡只剩型別擋不住的那些」就是分層的判準本身：**先讓記法擋掉能擋的，剩下的才交給檢查。**

### 反例（記法層本可擋、卻交給了守衛）

- **`AkashicService.init(root:key:…)` 的 `key: String? = nil`**（`#218`）。那個預設值讓「忘記帶 registry key」**寫得出來**，於是 CLI 三處各自漏一次，造成兩份 index、答案矛盾、在使用者的 `~/.akashic` 寫 live SQLite。修法是三處補參數 + 一條**源碼文字掃描**——而 verify 席指出真正的修法是**拿掉那個預設值**，讓它編不過。
- **`authorized ⊆ names`**（`#227`）。見上。

## 維根斯坦：這三層是「說」與「顯示」的分工

- **TLP 3.325**：「為了避免這些錯誤，我們必須使用一種**排除**它們的符號語言」。這就是記法層——**你不去取締你可以讓它寫不出來的東西**。
- **TLP 3.33／3.331**：符號的意謂一旦確定，邏輯語法的規則**自己就成立**，不需要另立型別論。反過來讀：**一條需要 validator 的不變式，是一個還沒寫對的記法。**
- **TLP 4.1272（形式概念）**：形式概念在記法中**顯示自己**，不由名稱代表。「是否 authorized」是名字的形式性質，把它做成 `names` 的兄弟清單，等於把形式概念當成材料概念——`docs/explainers/entity-vs-view.md` 已經抓過同一個病：「**是記法先犯的錯**」。
- **PI §201（規則悖論）**：任何行動都能被解釋成符合規則——**沒有任何範例表能決定一條規則**。M5 → M6／M7／M8 就是這句話的執行版：補一格、開三格。
- **PI §202**：遵守規則是一種**實踐**。這解釋了為什麼散文層的封閉列舉有效——它有效不是因為邏輯上無懈可擊，而是因為**必須有人手動去改那張表**，判斷住在那個動作裡。

一句話對照：**散文在「說」，而說會過頭；記法在「顯示」，而顯示不可能被違反；守衛的性質斷言是顯示在執行期的替身。**

> 誠實邊界：把《論考》用在 schema 設計上是**類比**。3.325 談的是命題符號不是 YAML。上面每一條的工程理由都能獨立成立；哲學給的是**更早的警覺**與**更準的命名**，不是論證的地基。同 `docs/explainers/logical-picture-future-and-questions.md` 立的規矩。

## 什麼時候「檢查」才是對的（封閉列舉）

以下 **4 類**是守衛層正當的場合。**封閉列舉，不得依性質相似類推第五類**——要加就改這張表並寫出理由：

1. **跨記錄的性質**。例如「沒有兩個 person 共用同一個 key」。那是**集合**的性質，單一記錄的型別表達不了。
2. **必須先載入才能報告的**。tolerant-preserve 要求未知欄位可載入（否則舊 binary 毀資料）；壞掉的記錄要能被讀進來才能 quarantine 並報出檔名。**把它變成不可表達，等於把診斷一起殺掉。**
3. **依賴求值時間的**。`Organization.authorized` 對「**當前有效**的名稱」的約束——哪些名稱當前有效隨時間變，型別在編譯期不知道。
4. **跨越程序邊界的**。store 是磁碟上的 YAML；型別系統不跨那條線，所以 decode 邊界一定要有檢查。

不在這四類、卻交給守衛的，就是**記法層欠了一筆**。欠著可以（見下），但要知道自己欠著。

## 遷移代價是正當的理由，但要寫下來

把不變式從守衛層搬到記法層通常是 **non-additive 的 schema 變更**：`#227` 那個要 format 5 → 8，而舊 binary 讀到會**整檔 quarantine（人檔消失）**。

所以「暫時留在守衛層」是合法的決定。**不合法的是不說。** 決定留下時，在守衛旁邊寫一行：這條本該住記法層，沒搬的理由是 X，追蹤在 #N。

否則下一個讀的人只看到一個「可以矛盾的結構」，而不知道那是一筆有意識的交易。

## 跟其他規則的關係

- **`common-spec-prose-enumeration.md`**：那條管**散文層**（列舉，別寫總括判準）。本條指出**守衛層的紀律相反**，並解釋為什麼——兩條不衝突，是分工。
- **`entity-backlink-completeness.md`**（**尚未在 main —— 待 `#225` 合併**）：那張 8→11→12 條的表兩次宣稱窮盡、兩次是錯的。最後的修法不是更嚴厲的告誡，是一段**可執行的稽核程序**——那正是本條「守衛述性質」在散文層的對應動作：**不要相信作者窮舉過，給一個能重跑的程序。**
- **`lossless-intake.md`**：那條管「進來的東西不得丟」。本條管「不變式該由誰保證」。

# 為什麼「中研院的人」不能是一筆記錄

> 這份文件是**解釋**，不是規格。規格在
> [`../design-principles-and-philosophy.md`](../design-principles-and-philosophy.md)
> §11（Entity admission rule 與形式概念禁令）與 §7（predicate 的定義域）。
> 哲學背景在同一份文件的 Part II（§14–§18）——本文引用它，不重述它。
> 追蹤紀錄在 [#54](https://github.com/PsychQuant/Akashic-Library/issues/54)。

## 一分鐘版

圖書館的書架上有一張標籤寫著「統計學」。標籤指出哪些書放在這一格。

現在把那張標籤**編目成一本書**：給它一個索書號、一筆 MARC 記錄、放進館藏目錄。

沒有任何東西會壞掉。目錄多了一筆，館藏量加一，它會出現在檢索結果裡、出現在年度統計裡、出現在「本館共有幾種資料」的答案裡。而它不是一本書——它是**用來談書的東西**。

`entities/` 是館藏目錄。view 是標籤。這份文件記錄一次真的把標籤編目進去的過程，以及為什麼當時看起來完全合理。

## 這次到底發生了什麼

2026-08-02，討論到「中研院的人」這個概念該怎麼存。AI 開了 [#54](https://github.com/PsychQuant/Akashic-Library/issues/54)，主張它應該是：

```yaml
# entities/<uuid>.yaml
type: view
key: iss
name: 中研院統計所
predicate: profile.affiliations 匹配 ...
```

使用者的糾正是：

> view 不是 netity 吧，他是 index 吧，你搞混了，這個專案的基本設計要區分 entity 跟不是 netity 的東西

糾正是對的。但接下來查證時發現的事情更重要：**提議者並沒有誤讀規則。規則核准了它。**

### 對照當時的 §11 Entity admission rule

當時的條文是「符合下列**多數條件**時，才 SHOULD 升格為一級 entity」。逐條給「中研院的人」這個 view 打分：

| # | 條件 | view 符合嗎 |
|---|---|---|
| 1 | 需要跨紀錄保持穩定身分 | ✅ 這個 view 要能被重複引用 |
| 2 | 名稱改變後仍應被視為同一物 | ✅ 改叫「統計所同仁」還是同一個 view |
| 3 | 有自己的生命週期或歷史 | ✅ 判準會修訂 |
| 4 | **能成為多種關係的端點** | ❌ 沒有東西引用 view、與 view 共同著作、隸屬於 view |
| 5 | 需要獨立查詢、引用或裁決 | ✅ 就是拿來查的 |
| 6 | 已有反覆出現的實際使用案例 | ✅ 這個需求反覆出現 |

**5 比 1。多數決通過。**

唯一不符的第 4 條，恰恰是唯一有判別力的那一條——而多數決讓它被其餘五條輾過。這不是規則被繞過，是規則**按照它自己的算術**核准了一個範疇錯誤。

### 為什麼多數決在這裡是錯的機制

多數決假設所有條件度量的是**同一件事的不同面向**，於是「符合得多」就是「更像 entity」。但第 4 條度量的不是程度，是**層次**：它問的是「這東西在世界裡，還是在我們用來談世界的工具裡」。

層次問題不能投票。一個東西在工具層，不會因為它在其他五個面向上都很像世界裡的東西，就搬到世界裡去。

修法因此不是把第 4 條的措辭寫清楚（措辭再清楚也會被 5:1 輾過），而是**把它抽出多數決，變成必要條件**，並把它改寫得比原本鋒利（見下一節）。

## 判準為什麼從「關係端點」改成「決定形狀」

原第 4 條「能成為多種關係的端點」有一個弱點：**它可以被製造出來**。

有人可以說：「那我在 view 記錄上加一條 `related` 關係指向它，這樣它就是端點了。」規則被滿足，範疇錯誤原封不動。判準若能靠補一筆資料來滿足，它就不是判準，是門檻。

現行判準改成一個**關於記法本身**的事實：

> 它決定了哪些欄位存在嗎？——也就是，載入器會為它分岔到不同的 decoder 嗎？

| 候選 | 載入器分岔嗎 | 弄錯的後果 | 是 entity 嗎 |
|---|---|---|---|
| person / work | 是 | **結構錯誤**：person 沒有 citekey，work 沒有職級時間軸。整份檔的形狀錯，改不動 | 是 |
| `article` / `book` | 否，同一個 decoder | **事實錯誤**：改一個欄位即可，記錄其餘部分意義不變 | 否，它是屬性值 |
| view | 否，而且沒有形狀可分岔到 | — | 否 |

這個判準加不出來。你無法靠補一筆資料讓載入器多一個分岔——那要改 code。

切點落在「這個值決定哪些欄位存在」的高度是有理由的：在它之上，種類不是關於那個東西的事實，而是**你用來談它的句子的形狀**；在它之下，它只是固定形狀裡的一個值。第二個理由是所有權：切點之下的分類法（`article` / `incollection`）是 BibLaTeX 與 Zotero 的，會在本專案沒同意的情況下增長；切點之上是本 store 自己的承諾。

關係端點測試保留為**佐證徵候**——沒有東西引用 view、與 view 共同著作、隸屬於 view，這個觀察仍然有用，只是它不再是判準。

## 是記法先犯的錯

責任不全在提議者。當時的檔案長這樣：

```yaml
type: person     # ← 形式種類：決定用哪個 decoder
type: article    # ← 書目類型：固定形狀裡的一個值
```

**兩個邏輯層次的東西住在同一個 key 裡，看起來是平輩。** 當 `person` 和 `article` 是兄弟，`view` 就是一個再自然不過的第三個兄弟。記法在邀請這個錯誤。

而且它不會抗議。實測：把一個內容為

```yaml
id: 0197D3B0-0000-4000-8000-000000000001
citekey: view-sinica-people
type: view
title: 中研院的人
```

的檔案放進 `entities/`，執行 `akashic validate`：

```
✓ 1 entries、0 people、0 libraries 全部通過
```

`akashic doctor` 把它算成一篇著作（`entries: 1`）。原因在判別函式的全稱後備：

```swift
let t = map["type"]?.scalar?.string
return t == "person" ? .person : .work     // ← 任何字串都是 work
```

封閉集合（work / person）在序列化到 YAML 的那一步，被這個 `? :` 悄悄變回開放集合。這個缺陷由獨立的 change 修復（把形狀名改成裸標籤、取自封閉集合、判別不出來一律 quarantine）；本文只記錄它在這次誤判中扮演的角色。

**教訓**：當同一個錯誤被反覆犯，先看記法有沒有在邀請它。抽象規範擋不住一個看起來理所當然的寫法。

## 形式概念與真正的概念

§14 已經鋪陳《邏輯哲學論》的圖像論，本節只補它未涵蓋的部分：**形式概念**。

Tractatus 4.126 區分兩種概念。「人」、「紅色」、「在中研院任職」是**真正的概念**（eigentliche Begriffe）——它們出現在命題裡，命題可真可假。「對象」、「事實」、「數」、「函數」是**形式概念**（formale Begriffe）——它們不是關於世界的性質，而是關於**表達方式**的性質。

關鍵句在同一條：

> 形式概念隨著一個落在它之下的對象一起被給出。

你不能先有對象、再補一句它的形式。有了那筆記錄，形狀就已經給定了。

4.1272 說明把兩者混淆的後果：形式概念的正確表達是**變元**，而「當作真正的概念詞使用時，就產生無意義的偽命題」。同一條舉的例子是：不能像說「有書」那樣說「有對象」。

4.1211 給出最清楚的類比：命題 `fa` **顯示**對象 a 出現在它的意義之中。你不會再附加一句「而且 a 是一個對象」——那句話沒有增加任何東西。

對照到這個 store：一筆帶著 `key` / `names` / `profile` 的記錄，它是 person-shaped 這件事已經被它的欄位組成顯示出來了。

而 3.333「函數不能是自己的論元」給出 view 成為 entity 之後的具體災難：它會同時出現在兩個層次——既是被選取的東西，又是選取的工具。一個 view 可以匹配到它自己。

## predicate 之間的關係怎麼表達

「隸屬適用於人，不適用於作品」——這句話該存在哪裡？

Tractatus 4.124–4.125 的答案是：這是**內在關係**（interne Relation），而

> 可能情境之間的內在關係，透過表達它們的句子之間的內在關係表現出來。

也就是說，predicate 之間的關係不能再用一個 predicate 去說；它顯示為兩個**記法**之間的關係。

現況正好是對的：person 記錄帶隸屬欄位，work 記錄不帶。**「隸屬不能形容 work」沒有任何一行程式碼在陳述它，它由那個欄位的缺席所顯示。**

危險在下一步。兩個看起來很自然的擴充都會摧毀這個顯示：

**被否決的方案一：通用邊表 `(subject, predicate, object)`。** 三元組把所有 predicate 變成平輩、所有實體變成平輩——正如 `String` 把指涉與標籤變成平輩、`type:` 把形式種類與書目類型變成平輩。這是同一個攤平錯誤的第三次。在三元組裡沒有東西阻止 `(article-uuid, affiliated-with, org-uuid)`：它不會壞，它會被接受。

**被否決的方案二：加一張表宣告每個 predicate 接受哪些 subject。** 正中 4.1272——把形式概念當成真正的概念來用。而且它有一個立即的工程後果：那張表存在的當下，「擴充一個 predicate 的定義域」與「新增一筆事實」變成同一個動作，一個 INSERT。文法變更與主張再也無法區分。

規則因此是：predicate 以欄位形式住在它適用的形狀上；圖與三元組只作為衍生層存在（可重建，所以攤平的損失可回復）。

## 表層文法騙人的地方

「隸屬」在中文裡只有一個詞，`affiliation` 在英文裡也只有一個。但它至少是兩個 predicate：

| 說法 | 實際是什麼 | 住在哪 |
|---|---|---|
| 某人隸屬中研院 | 僱用／成員關係，**有任期、可中斷、可重複** | person 記錄的隸屬時間軸 |
| 統計所隸屬中研院 | 部分—整體，通常隨機構存續 | organization 記錄的上級關係 |
| 某論文隸屬中研院 | **不存在**。看似成立是因為它是作者當時隸屬的簡寫 | 無此欄位——由作者 join 出來 |

第三列最危險，因為它讀起來完全通順。一篇論文「出自中研院」是日常說法，但它在 store 裡是一個**衍生**事實：由作者在該時間點的隸屬推出來的。把它存成正典，就是把衍生物當本體。

§15 說 store 本身也是語言遊戲；這裡的推論是：**自然語言用同一個詞，不構成它們是同一個 predicate 的證據。** 合併它們就是把定義域攤平，等同於通用邊表的縮小版。

## view 是 aspect，不是部分

使用者在討論中的說法是：

> 全部都是人，只是不同的 view 不一樣

這正是後期維根斯坦的 **Aspektsehen**（面向知覺）。兔鴨圖沒有變成兩張圖——圖是同一張，變的是你在它身上看見哪個面向。「中研院的人」不是從人群裡切下來的一塊，而是看人群的一種方式。

### 為什麼不叫 slice

考慮過「slice」這個詞，否決了。mereology 的「部分」需要**確定的邊界**：一塊蛋糕是蛋糕的部分，因為切下來的是哪一塊是定的。

而「中研院的人」沒有確定邊界，因為 [#20](https://github.com/PsychQuant/Akashic-Library/issues/20) 的 valid-time 時間軸讓它的外延取決於時間參數。同一個人在 2010 年在裡面、在 2020 年不在。你必須先固定時間，才有一組確定的人。

**誠實的反駁**：有人會說「固定時間之後，那就是一組確定的個體，那不就是一個部分嗎？」——是的，但那個確定的集合**從來沒有被存進 store**。store 存的是每個人各自的隸屬時間軸；集合是每次查詢時算出來的。所以正典層裡並不存在那個部分，只存在算出它的方式。那個「算出它的方式」就是 view。

## 這套論證的界限

**重要：以上的 Tractatus 論證不適用於「人」這個概念本身。**

Tractatus 的形式概念是「對象」、「事實」、「函數」、「數」、「複合物」這一類。**「人」不在裡面。**「蘇格拉底是人」在 Tractatus 裡是一個**完全合法的命題**——它有真假、有訊息量、可能是錯的。維根斯坦沒有說它無意義。

本文的論證只適用於 store 裡的 `person` 作為**記錄形式**（決定哪些欄位存在），不適用於「某個體是人類」這個關於世界的主張。同一個中文詞覆蓋兩件事：

| | 是什麼 | 哪一側 |
|---|---|---|
| 「這個個體是人類」 | 關於世界的主張，可真可假 | **真正的概念**，可以說 |
| store 裡的 person 形狀 | 這筆記錄的形式——哪些欄位存在 | **形式概念**，顯示 |

若有人拿本文的論證去主張「不能斷言某人是人」，那是過度推廣。

### 維根斯坦真正用蘇格拉底舉的例子

是 5.4733，而且它的診斷方向對本專案更有用：

> 「蘇格拉底是同一的」這個命題之所以什麼都沒說，是因為我們沒有給「同一的」這個詞作為性質詞任何意義。

失敗**不在形上學**（不是「世界上沒有同一性這種東西」），而**在記法**——沒有給那個符號在那個位置一個用法。「同一」有完全正當的用法，只是不在那裡（5.53：對象的相同用**符號的相同**表達，不用等號）。

`view` 完全一樣：它不是壞字，它在 `config.yaml` 裡有正當用法。它只是在 `entities/` 檔案的形狀位置上沒有被賦予意義。**位置錯誤，不是詞彙錯誤。**

而前一條 5.473 是「邏輯必須自己照顧自己」——這正是本專案的修法方向：不是在文件裡多寫一條禁令就算數，而是讓記法自己擋下來（quarantine）。散文負責讓人理解，記法負責執行。

**推論到錯誤訊息**：只說「不認得的形狀 `view`」只完成一半——那只證明它在這個位置沒有意義。完整的診斷還要說出它在哪個位置**有**意義。這就是為什麼 quarantine 理由必須指出「view 的判準屬於 `config.yaml`」。

## 這個設計需不需要共相

不需要，而且結構上排除了。但要先分清楚：**反共相的思路屬於後期維根斯坦，不屬於 Tractatus**，兩者的論證與結論都不同。

- Tractatus 的顯示／說：形式**是**確定的，只是不能被說出來，只能顯示。
- PI 65–67 的家族相似：可能**根本沒有**共同的東西。「別想，要看！」——不要預設所有被叫做「遊戲」的東西必有共同性質。

PI 68–69 的推論對本專案更直接：概念的邊界是**為了某個目的畫出來的**，不是被發現的。所以形狀的封閉集合（work / person / organization）是**規定**，不是本體論發現——這與 §16「規則無法唯一決定所有未來應用」一致，也與 §11 新增條文所附的誠實邊界一致。

而標籤的意義是**載入器拿它做什麼**（PI 43；維根斯坦自己對這句加了「對一大類情況而言」的限定，不是無條件的）。這是一個用法式的、去形上學的讀法，不需要任何抽象實體。

由此得到一條可機械檢查的不變式：

> 如果 `person` 是一個共相，你會預期 store 裡有一筆記錄代表「人性」。**沒有，而且不能有**——理由與 view 不能是 entity 完全相同。

`entities/` 裡住的是世界中被指涉的東西；形狀名是用來談它們的記法。**標籤永遠不會是它自己所標示的那種東西。** 讓它成為實體，就是讓它同時出現在兩個層次——3.333 的「函數不能是自己的論元」。

## 那 view 該放哪

[#54](https://github.com/PsychQuant/Akashic-Library/issues/54) 的結論分兩半：

- **判準**（「隸屬時間軸匹配中研院」這個條件本身）→ `config.yaml`。它是設定，不是知識。
- **外延**（實際符合的那組人）→ 衍生索引。它可以隨時丟掉重算。

導致原始誤判的推論鏈值得記下來，因為它看起來很有力：

> view 的判準無法從 canonical files 重建出來 → 所以它不是衍生資料 → 所以它是 canonical → 所以它該進 `entities/`

**第二步到第三步無效。**「推不回來」只證明它不是 derived data，不證明它是 canonical knowledge。第三個可能性一直都在：**它是設定**。

設定與知識都不可從資料重建，但它們的地位完全不同：知識描述世界，設定描述你想怎麼看世界。把設定存進 `entities/`，就是本文開頭那張被編目成書的標籤。

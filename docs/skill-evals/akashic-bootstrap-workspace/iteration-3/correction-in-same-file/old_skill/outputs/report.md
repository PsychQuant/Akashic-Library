## 先說最重要的問題：這份檔案裡有 2 列其實是同一篇論文

第 2 列與第 4 列不是兩篇不同論文，是**同一篇的「原始文章」與「更正公告」**：

| 列 | Article Title | 作者（短） |
|---|---|---|
| 2 | Adaptive designs for dose-finding in early phase oncology trials | Chen, YT; Wang, SM; Ablm, KLT |
| 4 | Adaptive Designs for Dose-Finding in Early Phase Oncology Trials **(vol 44, pg 210, 2025)** | Chen, YT; Wang, SM; Tsai, KL |

標題尾端的 `(vol 44, pg 210, 2025)` 是 WoS 的標準更正公告格式——標題本體＋被更正之原始文章的卷期頁與年份。期刊名、年份完全一致，標題除大小寫與該尾綴外逐字相同，可判定為同一篇論文的兩筆索引記錄，不是兩篇獨立論文。

**含意**：這篇論文只有 3 個作者槽，不是 6 個；且第 4 列（更正公告）在這裡剛好帶有比第 2 列更準確的第三作者姓名（見下）——更正公告本身就是在修正原始索引的錯誤，這裡抓到了一個實例。

第 3 列（`Lin, PC; Ho, CY`）是另一篇獨立論文，與上述無關。

**外部核對嘗試**：用兩篇的標題查了 Crossref（`query.bibliographic`），兩者皆**查無吻合記錄**（回傳的候選在作者、期刊、主題上都對不上）。推斷這份匯出是測試用的合成資料，不是可外部驗證的真實文獻——本報告的判定因此完全依賴檔案內部證據的交叉比對，沒有外部資料庫可以再確認。

## 問題摘要（直接說的部分）

1. **列 2 與列 4 是同一篇論文的兩筆記錄**（原始文章＋更正公告），若照「一列一個 work」的預設處理會建出重複的論文實體，且會把同一個作者槽誤算成兩個獨立出現次數。建 work 時這兩列要合併／建立更正關係，不要各自獨立造 entry。
2. **`Wang, Shu-, I` 的給名拼法無法確定**：短式縮寫（`SM`）與全名欄位（拆解後為 `S`、`I`）互相矛盾，且這個矛盾在原始文章與更正公告兩筆記錄裡一模一樣地重複出現——更正公告沒有把它一併修好，代表這不是「查另一筆記錄就能解的分裂」，需要人工回頭問圖書館／原始資料庫，或找這篇論文的其他外部佐證（本次 Crossref 查詢找不到這篇論文，無法用它反查）。**不要用「Shu-I」或「Shu-Min」這類猜測值建 person**——依 skill 的紀律，一筆錯的姓名比一筆缺的姓名更難事後發現。
3. **`Ablm, Kai-Lun Tsai` 本身是一筆會誤導的資料**：如果只看列 2（原始文章）而沒有比對到列 4（更正公告），會誤以為存在一位姓氏是 `Ablm` 的作者，並可能把 `Tsai` 當成他的第二個給名建進資料。這是本檔案裡示範的「同一份匯出檔藏著自我更正線索」的情況——判斷依據必須做跨列比對，不能逐列獨立處理。
4. 以上判定完全基於這 3 列資料本身的交叉比對；沒有查到任何外部記錄（Crossref）可供反向驗證，本報告的「高確定」是相對於「檔案內部證據一致且收斂」而言，不是「已對到外部資料庫」的那種確定。實際建 person 前，仍建議先跑 `akashic_person(name:)` 看 store 裡是否已有這幾位的候選（含可能已存在的 literal 或 person_key），本次分析未執行此步驟。

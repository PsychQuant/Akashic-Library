# 三個 hardening 缺口：`--out` 穿透 symlink、全鏈無大小上限、`--library` 解析鏈與 README 分岔（#519，follow-up from #516 verify）

三個缺口互不相干，共同點只有一個：**都是「能跑、沒擋」**。#516 verify 量到它們時全部標非阻擋，
因為它們都在那一輪的 in-scope 之外（介面選擇或跨 core）。

## Expected 1 —— `--out` 穿透 symlink

`ln -sf victim.txt outlink.json` 之後 `--out ./outlink.json` **改到了 victim.txt**——寫入
逃逸到另一條路徑，而 symlink 本身原封不動（#516 verify 實測）。

**裁決：原子寫入 ＋ 非普通檔一律拒絕，不加 `--force`。** 三條，順序固定：

1. 目標存在且**不是普通檔**（symlink／目錄／FIFO／socket／device）→ 硬錯誤、具名、零寫入
2. 否則同目錄開 temp、寫完 `os.replace()` 原子替換
3. **無論成敗**，把解析後的絕對路徑印到 stderr

**為什麼拒絕 symlink 而不是「跟隨但原子替換」**：原子替換本身就不會逃逸（`rename(2)` 作用在
名字上、不跟隨 symlink），但那會把使用者刻意建立的導向**默默換成實體檔**。拒絕是唯一不做
假設的選項。

**為什麼不加 `--force`**：本 repo 對 `--force` 有明文立場（`idd-close`：「第一次是我趕時間，
第三次就變成反正都 force」）。重跑覆寫這個中間產物是**常態**動作；把常態放進旗標後面，訓練
出來的正是那個反射，而反射一旦養成，旗標對真正危險的那次也不會攔住。

**為什麼印絕對路徑**：`--out ~/.akashic/store.yaml` 這種**指錯地方**，上面兩條都擋不住（它是
普通檔），加旗標也擋不住（旗標防的是「不小心覆寫」）。可見性才是對症的。

**TOCTOU 的誠實邊界**：第 1 條與第 2 條之間有窗，但那個窗**不會造成逃逸**——`os.replace` 換的
是名字，即使競爭者剛插入一個 symlink，被換掉的也是那個 symlink 本身。第 1 條買到的是「拒絕」
而不是「不逃逸」，兩者是不同的性質，註解裡分開寫。

## Expected 2 —— 全鏈無大小上限

5 MB 摘要 → RSS 46.6 MB、`proposals.json` 5.0 MB，原樣流進 store 的 YAML 欄位；腳本無 cap，
`AddOnlyEnrichment` 亦無（長度檢查 grep 0 命中）。

**裁決：上限放 core，語意是拒絕不是截斷，值 65,536 位元組。**

**位置：core。** 診斷期間掃到的 sister concern 是決定性的——`enrich-from-zotero`（#340）走
**同一條 core 路徑**、同樣無上限。裁在腳本端只保護這一條鏈，而缺口的形狀跟 adapter 無關：
它是「core 收下任意長的字串」。實測三個消費端全部覆蓋：`AkashicService.enrich`（CLI 與 MCP
共用）與 `ZoteroEnrichment.plan`。

**語意：整批拒絕、零寫入、具名，不截斷。** `plan` 在做任何規劃之前先把全部提案 `map(validate)`，
所以拋出即整批零寫入——與 `two-kinds-of-edits` 對程式編輯的既有義務（「可預期失敗整批擋零寫入」）
一致。截斷會讓一個**不是來源給的**值進 store 且不出聲。

**單位是位元組不是字元——裁決文字的單位混用，這裡更正。** 裁決寫「64 KiB（65,536 **字元**）」，
而錨點 `AliasEventBudget.maxBytes` 是位元組，CJK 摘要下兩者差三倍。同一段裁決引的 p99／中位
（2,185／1,136）逐一吻合位元組量測，可見它本來量的就是位元組。

**max 那個數字也對不上，以重量為準。** 裁決寫「最長 3,884」，重量得 **4,220 bytes**。差別的
來源是抽取式：**長 value 會被 YAML 折行**，行為單位的 grep 讀不到完整值（本 repo 在 `zero-instance-guards`
第 13 列的量測踩過同一個坑）。本輪改用 PyYAML 解析。

| | 值 |
|---|---|
| abstract 筆數 | 1,517 |
| 最長 | **4,220 bytes**（3,226 字元） |
| p99 ／ 中位 | 2,185 ／ 1,137 |
| 上限 65,536 對最長值的餘裕 | **15.5 倍**（裁決寫 16.9，那是用過期的 max 算的） |
| 上限對 `AliasEventBudget.maxBytes` | **1/128**（測試釘住這個比例） |

（對照組：#516 verify 那個 5 MB 摘要是本上限的 **80 倍**。）

### 這一項動到了 `lossless-intake` 的封閉列舉，所以顯式改了那個檔

該規則說不收的只有兩類、**不得依性質相似類推第三類**。加上限看起來像加第三類，但**它不是**，
而把它寫成第三類會產生真的危險：那張表的成員資格是「**可以丟掉這個欄位、繼續匯入**」，一個以
「大小」為名的成員會被下一個人類推成「太長的欄位可以丟掉」——那正是該規則第 3 條執行細節禁止
的靜默丟棄。

所以加的是一節**分開圍起來的**「有界拒絕」，並寫明它為什麼不在那張表裡：兩者的失敗形狀相反
（收一部分 vs **一筆都沒收**；可能不知道 vs **必然知道**；事後不可判定 vs **可**——來源原封
不動）。該節另附五條邊界條件，缺一即回到規則的禁令之內。

`zero-instance-guards` 加第 18 列（今日零實例）。**理由欄不沿用既有 17 列任一條**：前十七列
的零都是關於**已經在庫裡的東西**，這一列的零**量的是出口而守衛裝在入口**——庫內最長 4,220 bytes
是因為進得來的都小，而這道檢查管的是 adapter **這一次遞過來**的字串。與第 16 列（已知會漲的
曲線）最像而不同：**沒有曲線**，實例會由一次外部呼叫一步跨過，而 #516 verify 已經一步跨過 80 倍。

## Expected 3 —— `--library` 解析鏈與 README 分岔

腳本只認 `$AKASHIC_LIBRARY` → `~/.akashic`；`README.md:223` 記的是 `--library` →
`$AKASHIC_LIBRARY` → `$AKASHIC_HOME/config.yaml` 的 `current`。

**裁決：明寫限制，不接 `config.yaml`。** 接上去意味著這支 Python 腳本要**重新實作** registry
的解析鏈。那不是消除第二份副本，是把「一份**描述**的副本」換成「一份**實作**的副本」——而後者
更糟：描述分岔了讀得出來，實作分岔了只有在特定 profile 下才會顯形。

風險有界這件事支持這個方向：`--source` 是 digest 時走內容定址，library 取錯只會「找不到那個
digest」——**可見的失敗**。所以窄的解析鏈只要**誠實**就夠，不需要完整。

`--help`、docstring 與 `SKILL.md` 三處明寫。**`README.md:223` 不改**——它描述的是 **CLI** 的
解析鏈，那是對的；要改的是腳本這一側從未說明自己更窄。

## 實作期間自己踩到的兩個缺陷

**(1) `mkstemp` 寫在 `try` 之外。** 它會在父目錄不存在時拋 `FileNotFoundError`（`OSError` 的
子類），寫在 try 外就變成 traceback 而不是承諾的具名錯誤。**既有的 fixture 測試（case 8，
#516 加的）就是為這件事存在的**——它抓到了本輪的迴歸。

**(2) 錯誤訊息用一句話蓋兩種情形。** 第一版對目錄／FIFO 也印「跟隨它會改到另一條路徑上的檔」，
那句話**只對 symlink 為真**。改成按類別分。

## 自審（跨模型席回覆之前）找到的三項

**(3) `sourceDigest` 不在上限之內，而註解寫「每一個字串」。** 它不進 store（既有測試釘著），
但**會回顯進報告**——MCP 面的報告直接進 LLM context，那正是上限要管的出口。補進去而不是把
註解改小；加一格測試釘住。

**(4) 覆寫會把既有檔的權限從 `0644` 換成 `0600`。** `mkstemp` 建 `0600`、`os.replace` 換 inode，
所以原檔的 mode 沒被保留（實測）。**不還原**：`proposals.json` 裝的是第三方逐字摘要（含出版商
版權聲明，SKILL.md 已載明），`0600` 對這個內容更對。寫出來是因為它是**安靜的**行為改變。

**(5)「1/128」是未跳脫的比值。** `AliasEventBudget.maxBytes` bound 的是**輸入檔**的大小，而 YAML
序列化會放大 value。實測（真的走 `create-entry` 寫檔再量檔案）：

| value 形狀 | 放大 |
|---|---|
| ASCII／反斜線／引號／CJK／換行 | **1.00×** |
| `\t` | **2.00×** |
| 控制字元（`\x01`／`\x7f` → `\xNN`） | **4.00×** |

所以 65,536 bytes 的 value 落到磁碟最壞約 262 KB ＝ 輸入預算的 **1/32**。結論不變（單一欄位不會
主導整筆記錄的預算），但那個數字是 1/32 不是 1/128——`AddOnlyEnrichment` 的 doc 與
`zero-instance-guards` 第 18 列都改了。

## 兩個補量測（一個是真邊界，一個是量到的否定發現）

**`lstat` 只查最後一段，父目錄若是 symlink 仍會穿透。** 實測 `ln -s real link` 之後
`--out link/out.json` 落在 `real/`。這是刻意的範圍——第 1 條防的是「寫穿到另一個**檔**」，
目錄層的重導向是檔案系統的正常語意——但它**削弱第 3 條的可見性承諾**：印出來的是未解析的
路徑。**不改成印 `realpath`**：macOS 的 `$TMPDIR` 本身就是 `/var → /private/var`，那會讓每次
正常執行都多印一行雜訊，而第 3 條要對付的是**打錯目標**（那種情形兩條路徑相同）。

**過長的欄位鍵不會回顯洩漏——兩面都量過。** 上限訊息裡有 `欄位「\(key)」的值`，而一個
剛好在界內的 64 KB 鍵會先通過 `checkLength`（鍵先於值檢查）再被印進值的訊息。實測 2,000 字元
的合法鍵：**CLI 406 字元、MCP 真 binary 413 字元**，兩面都以 `…（已截斷）` 收尾。既有的
消毒顯示形已經涵蓋，不必另加。

## 誠實邊界

**上限的三個消費端只有兩個被端對端實測**：CLI（`akashic enrich`）與 MCP（真 binary，stdio
驅動）。`ZoteroEnrichment` 走同一個 `AddOnlyEnrichment.plan`，那是**讀程式碼**得到的結論，
本輪沒有為它跑一次端對端。

**TOCTOU 的窗仍在**（見 Expected 1）。它不造成逃逸，但「拒絕」這個保證在競爭下不是原子的。

**`--out` 的可見性只到 stderr。** 指錯地方時使用者要**看**那一行；沒有任何機制在他不看時攔住。
這是裁決明知的取捨（替代方案是加旗標，而那被上面的理由排除）。

**CI 仍未驗證**：GitHub Actions 帳務擱置，全部只在本機。

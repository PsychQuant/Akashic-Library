# 寫下一句可能是錯的話之前，先回答四個問題

適用於**會被別人讀來行動的交付物**：issue 的 Expected／Actual、診斷與分析報告、規則與規格、closing summary，以及本 plugin 各 skill 產出的判定與報告。

不適用於**不交付的推敲**。判準是「**會不會被別人讀來行動**」，不是載體種類。

## 為什麼是問題不是分類法

這條規則的前兩版都是分類法（把句子歸類，再依類別決定受不受管）。兩版都被跨模型審查打掉，而且是同一個原因：**每一條分類邊界本身都是一個關於命題世界的斷言**，於是規則的斷言表面比它要管的東西還大。第二版的分類法連它自己舉的例子都歸錯（見下方「這份文件犯過的錯」）。

問句沒有真假，所以沒有邊界可破。**下面四個問題不需要你先判斷這句話屬於哪一類**——你只要能回答，就合規；答不出來，就照第 4 題的出路寫。

## 四個問題

### 1. 這句話有沒有可能是錯的？

有可能 → 往下走。不可能 → 本清單不管它。

「不可能錯」的典型是**規定用語**（「本檔所稱 X 指……」）與**表達決定**（「我們選 A 不選 B」）。但注意：一句**描述**現況的話即使長得像定義，仍然可能錯——「`VenueType` 是封閉三值」讀起來像約定，實測是**六值**，一條 `grep` 就否證。**分不清就當成有可能錯**，成本只是多回答三個問題。

### 2. 我憑什麼說它？

寫出證據**是什麼**、**怎麼取得的**、**什麼時候**。

- 能用指令取得 → 附指令。但**指令是程序不是證據**：跨網路的查詢明天會給不同答案，所以同時寫下**當次觀察到什麼、哪一天**。
- 證據不是指令能取得的（人的裁定、印刷文獻、需要綜合判斷的身分歸屬）→ 寫出證據**來源**與**取得方式**。身分與歸屬的判定另有規定：見下方第 5 節。
- **取不到證據** → 走第 4 題。

### 3. 我手上的東西還說了什麼，是我沒讀的？

這一條是本規則最貴的一課，因為**這份文件在上一版就犯了**：查三筆記錄有沒有頁碼，腳本只印 `page` 欄，於是寫下「能寫的最強結論就到這裡」——而**同一份回應裡有兩筆帶著 `article-number`**，答案本來就在手上（實測見下）。

**投影窄於命題，和結論寬於觀察，是同一枚硬幣。** 取回一份資料之後，先看完它，再決定能寫什麼。

### 4. 我寫下的範圍，有沒有超出證據的範圍？

- 查了 A、B、C 三個來源都沒有 → 寫「**在 A、B、C，以查詢 Q，於某日查無**」，不寫「沒有」。
- 量了一個實例 → 不寫全稱句。
- 沒查 → 限定詞**寫在句子裡**（「推測」「待查」），並寫出**要查什麼**才能定案。限定詞不是免死金牌：**證據便宜又拿得到時，去拿，不要用「推測」帶過**——本規則的兩個立案失敗都是「有能力查卻沒查」。

## 5. 身分與歸屬的判定另有規定

判定「這個 literal 作者就是這個人」「這個刊名就是這個 venue」時，本清單**不重述**該領域的判準——重述會走樣（前一版對兩份規則的就地重述共有六處失真，全部由跨模型審查逐句比出來）。

實際規定住在 Akashic repo 的 `.claude/rules/identity-is-judged-not-matched.md`。**該 repo 是 private，沒有存取權的讀者（含未認證的 agent）取不到全文。**

取不到時的出路是**明說取不到**，不是憑印象補上：把「依據該規則的哪一條」寫成待確認，或請有存取權的人補。**不要憑記憶重述一份你讀不到的規範。**

## 這份文件犯過的錯（每一條都由跨模型審查抓出、由我複驗）

留著是因為只寫結論的話，日後的維護者會覺得這份清單囉嗦而把它總括掉——而那正是前兩版壞掉的方式。

| 錯 | 實況 |
|---|---|
| 拿一句假話當「不可能錯」的例子 | 寫「`VenueType` 封閉三值」，實測六值（`periodical`／`conference`／`publisher`／`database`／`socialMedia`／`website`）|
| 只讀了手上資料的一部分就下結論 | 見第 3 題 |
| 就地重述讀不到的規範 | 對兩份 private 規則的重述共六處失真——漏證據項、把開放清單寫成封閉、漏掉識別碼例外、把「觀察」寫成「判準」、加上原文沒有的排序 |
| 引用先例卻沒查那個先例 | 用「plugin 既有慣例」正當化改用絕對 GitHub URL，而那條既有慣例實測**自己也 404** |
| 揭露不對稱 | 對 Akashic repo 揭露了 private，對同樣 private 的另一個 repo 沒有 |

## 兩個立案失敗（有界陳述＋可重跑的指令）

### 一、`kiki830621/storyline` 的 issue #7（**該 repo 為 private，無存取權者讀不到該 issue**）

該 issue 的 Expected 假設某筆記錄 `pages` 欄的 16 位數字是「某種外部 ID」，並據此提了兩個修法。**那個假設寫下時沒有查證。**

把該數字當成 DOI 後綴反查，2026-08-21 觀察：

```bash
curl -s -H 'User-Agent: your-tool (mailto:you@example.com)' \
     https://api.crossref.org/works/10.1177/1948550610386628 \
  | python3 -c "import json,sys; m=json.load(sys.stdin)['message']; \
      print(m.get('DOI'), '|', (m.get('title') or [''])[0][:40], '|', m.get('volume'), m.get('issue'), m.get('page'))"
# 當次回傳：10.1177/1948550610386628 | The impact of illusory fatigue... | 2 3 231-238
```

**能寫下的**：當次 Crossref 對該 DOI 回傳 `volume 2 / issue 3 / page 231-238`，且回傳的標題與該記錄相符。
**不能寫下的**：「真值就是 231-238」——掛在識別碼下的欄位仍可能誤植（本 plugin 的 `references/work-sources.md` 記過一個實例）。要更強的結論需要出版商頁或全文。

### 二、一份逐列對照報告的一句話

原句：「出版都超過半年了，卷期頁碼照理已經確定。可用 DOI 向出版商查一次補齊」。**「照理已經確定」沒有查證。**

2026-08-21 觀察（同時印 `page` 與 `article-number`——這正是第 3 題的教訓）：

```bash
for d in 10.3791/68984 10.1007/s44195-025-00108-7 10.1007/s11009-025-10201-6; do
  curl -s -H 'User-Agent: your-tool (mailto:you@example.com)' "https://api.crossref.org/works/$d" \
    | python3 -c "import json,sys; m=json.load(sys.stdin)['message']; \
        print(m.get('page'), m.get('article-number'), (m.get('container-title') or [''])[0][:30])"
done
# 當次回傳：
#   None None  Journal of Visualized Experiments
#   None 23    Terrestrial, Atmospheric and Ocean
#   None 78    Methodology and Computing in Appli
```

**能寫下的**：當次三筆的 `page` 皆為 None；其中兩筆回傳了 `article-number`（23、78）。
**不能寫下的**：「這些刊物不用頁碼」——那是關於期刊政策的命題，需要期刊自己的投稿格式規格。

## 誠實邊界

**擋不住「我以為我查過了」。** 上面兩個失敗都是有能力查卻沒查。

**掛載機制只碰得到 skill 檔。** 本規則由各 skill 的 see-also 引用而生效，所以它實際到得了的是**寫 skill 時**與**跑 skill 時**。而上面兩個立案失敗一個在 GitHub issue 的 Expected、一個在分析報告裡——**兩者都不在 skill 檔內**。這是已知缺口，不是尚未發現的問題：**掛載面比適用面窄**。要真正涵蓋 issue 與報告，需要的是別的機制（撰寫時的 gate 或審查時的檢查），不是這份檔案。

**「曾經為真、因世界改變而變假」不在本清單內。** 那需要守衛而非紀律。本 plugin 自己就有一個實例：`.claude-plugin/plugin.json` 的描述寫「Store format 10」，而本機 store 的 `store.yaml` 寫 `format: 12`（單機觀察，未查證該描述寫下時是否正確、也未查兩者是否可相容）。追蹤：Akashic-Library#408。

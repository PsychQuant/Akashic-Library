# 寫入以 source of truth 為準——使用者的同意不能授權錯的寫入

適用於本 plugin 每個 skill 對 Akashic store 的**每一次寫入**：建檔、補欄位、身分判定、關係邊、library 成員、狀態與標籤。

## 規則

1. **每一筆寫入的值都有一個 source of truth**（下表）。寫入的依據是**你對照它查證過，並承認這個值是正確的**——不是「誰同意了」。
2. **使用者的同意必要，但不充分。** 同意決定的是：要不要做、做哪一批、在幾個都正確的選項之間挑哪一個。它**不能**讓一個錯的值變成對的。
3. **使用者要求的寫入與 source of truth 不符時，不是拒絕，也不是照寫，而是改成正確的東西再寫。** 乾跑報告裡逐筆寫出三件事：你要的是什麼、source of truth 是什麼、所以寫的是什麼。
4. **查不到 source of truth，或查了判不出來 → 不寫。** 列進報告，留在誠實的狀態（「判不了」「待人工判定」）。不因為使用者要求就寫。
5. **使用者可以提供證據，不能提供授權。** 使用者說「Crossref 錯了，論文首頁印的是 X」，那是新的證據：去核對它，核對成立就照它寫。使用者說「就寫 X」而沒有給出處，那不是證據——照第 3 條處理。
6. **source of truth 就是使用者本人的那幾類**（下表「依據」列），使用者的話就是查證結果，照寫。

## 各類寫入的 source of truth（封閉列舉）

**只有下表這幾類。** 表外的寫入，先把它加進這張表、寫出它的 source of truth，再寫——**不得依性質相似類推**到某一列。

| 寫入 | source of truth | 使用者的話在這裡是 |
|---|---|---|
| 書目欄位：標題、作者、日期、卷期頁、DOI、venue | 作品本身。作品本身與登記機構（Crossref、OpenAlex）不一致時以誰為準**尚未定案**（#639）；定案之前，兩者不一致就列為歧異、不擅選 | 線索 |
| 人物、venue、機構的事實欄位：ORCID、任期、ISSN、改名沿革 | 權威來源（ORCID 記錄、機構頁、ISSN 中心、期刊自己的沿革頁） | 線索 |
| 身分判定：literal → person／venue／organization 的 key、攣生合併 | 支撐判定的證據，連同理由寫進 verdict | 線索 |
| 關係邊：`cites` 等 | 施引作品本身——`cites` 的依據是那篇作品的參考文獻 | 線索 |
| library 成員：**規則型**（成員由規則決定，例如某期刊的全量） | 那條規則。哪些 library 屬於規則型、規則怎麼界定，目前只能讀 library 的描述判斷；正式的界定方式**尚未定案**（#642） | 線索 |
| library 成員：**主題型**（成員由人依主題挑選） | 使用者的選擇 | **依據** |
| 範圍：處理哪些作品、哪一批、要不要做 | 使用者的決定 | **依據** |
| 閱讀狀態、標籤、使用者自己的筆記 | 使用者本人 | **依據** |

「線索」的意思是：使用者的話告訴你**去哪裡查**，查到的東西才是寫入的依據。

## 為什麼

2026-09-24，`akashic-work-references` 把一篇種子論文的 56 筆被引文獻寫進 store，其中包括「掛進種子所屬的 library」。乾跑給使用者看過，使用者也指定了要掛的兩個 library——**同意是真的**。其中一個卻是一刊的全量目錄，成員由「OpenAlex 上該刊的 article 與 review」這條規則決定。56 筆裡有 52 筆不是該刊的作品，隔天經 verify 發現後移除（#642）。

同意沒有讓那 52 筆變成該刊的作品。而且就算提問時把 library 的描述一起列出來、使用者看了仍然說掛，結論也一樣：**目錄收什麼由規則決定，不由誰點頭決定。**

使用者對 #642 的裁定：

> 「其實你可以改成正確的東西之後寫入吧，我覺得因為這每一個東西都有source of truth，使用者也沒有權限要你寫錯誤的東西，必須要讓你承認這個是正確的才有可能寫入」

所以不是「拒絕並具名」，也不是「明確同意後照寫」：那 52 筆的正確寫法是**不掛進那個目錄，只寫正確的成員資格**。

## 誠實邊界

- **「承認這個是正確的」不是說你不會錯。** 它的意思是：你對照 source of truth 查過，查證的內容寫在乾跑報告裡，讓使用者能逐列看出你哪裡錯。使用者從授權者變成稽核者，所以乾跑報告**每一列都要帶依據**（查了什麼、在哪裡、看到什麼），不能只列結果。
- **本規則不取代「確認後才寫」。** 有判斷的寫入仍然要先乾跑、等使用者同意（各 skill 自己的流程）。本規則補的是另一半：同意之後，錯的仍然不寫。
- **表上兩列尚未定案**（#639 的書目來源優先序、#642 的規則型 library 界定）。定案前照表上的過渡寫法處理：不一致就列歧異、看不出來就問。

## 跟其他規則的關係

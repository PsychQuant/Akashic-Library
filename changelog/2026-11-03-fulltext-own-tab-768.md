# 2026-11-03～04 `fulltext fetch` 只讀自己開的分頁，而且不再關分頁（#768）

使用者正在用 Safari 時，`openOwnTab` 把「目前的分頁」當成剛開的分頁。站名也取自那個分頁，所以「還在同一個站才關」一定成立：使用者分頁的文字被讀，找不到連結時連分頁都關了（結束碼 3），真正開的分頁留著沒人管。

原因比 `currentTab()` 寬一層：Safari 沒有穩定的分頁 id，這個命令只用位置認分頁。只修第一步，分頁之後移動時同樣會打到別的分頁。

## 經過

- 第一版：比對開分頁之前與之後的清單認新分頁，之後每次讀都比對清單。verify 第一輪 FAIL（5 HIGH）：在我們的分頁裡開別的網頁與分頁自己換頁分不出來，讀了、還關了那一頁。
- 第二版：拿掉關分頁、以 `blocking_dialog.window_id` 認視窗、看不到就停。verify 第二輪 FAIL（2 HIGH）：最後一個分頁換頁會被當成新分頁、⌘W 接 ⌘T 會被接手。兩輪下來，每修一次位置推論，邊界就換一個地方，於是停下來請使用者決定。
- 使用者 2026-11-04 選定：以一次性 fragment 認分頁；`fetch` 不關分頁（取代 issue 的第三點）。量到 Elsevier 會丟掉記號之後，再選定「記號加位置追蹤」。
- 第三版（記號）：verify 第三輪 FAIL（2 CRITICAL、3 HIGH，同一件事）：記號還在時，導航用的 `safari-browser open --url-endswith '#akashic-…' <PDF>` 不會導航我們的分頁。safari-browser 的 `open` 自己判斷有沒有指定分頁（`OpenCommand.swift`，v2.7.0、v2.8.0 與 main 相同），不算 `--url-exact`／`--url-endswith`／`--url-regex`（safari-browser#233），於是在前景視窗開新分頁。保留記號的五家出版商、每一篇有 PDF 連結的文章都會中。假瀏覽器把這個呼叫當成導航，所以 19 個 mutant 看不見；兩次真機執行都沒走到這條（SAGE 沒有連結，Elsevier 已丟掉記號、用位置鎖導航）。同一輪也指出「頁面落定之後記號不見就停」（第三版自己加的）把腳本轉到的登入、驗證頁從 6／8 變成 1，Elsevier linkinghub 插頁還會誤停。
- 使用者 2026-11-04 對第三輪的裁決：記號鎖加 `--profile`；記號不見時照原決定改用位置追蹤。

## 改了什麼

第四版（第三輪 verify 之後）在下面各點之上：

- **記號鎖一定帶 `--profile`**：`--profile <P> --url-endswith '#akashic-…'`，`<P>` 是開頭讀到的視窗的 profile（恰好一個時；不只一個就退回位置鎖）。`open` 帶了 `--profile` 才會解析目標、導航那個分頁。`js`、`wait` 在同一段 AppleScript 裡重驗；`open` 不重驗（先解析、再以另一個 Apple event 導航）。假瀏覽器改成照真的 safari-browser 的判斷：沒有指定分頁的 `open` 找網址完全相同的分頁拉到前面，沒有就開新分頁。
- **記號不見就改用位置追蹤**，不論何時（拿掉第三版的 `markMayDrop`／`markGone`）。三個先前改成只測「記號不在」的測試現在兩種都跑。
- **別的 profile 的視窗開著，開任何分頁之前就停**（結束碼 1，訊息不印那個 profile）：#351 可能把新分頁開進那個視窗、以那個 profile 的身分載入文章頁。同一個 profile 的另一個視窗不擋（開錯視窗時 `fetch` 認得出來、不讀它）。#351 修好之後可以放寬（第六版收回：停止無條件，放寬要等 safari-browser#352）。
- **接續以記號找分頁**：結束碼 8 的 `resume:` 一行多印 `--window <N>`（執行當中視窗編號可能變了）與記號還在時的 `--resume-mark <記號>`。接續時先找網址以它結尾的分頁（位置移了也找得到；在別的視窗或有兩個就停），找不到才照 `--resume-tab` 的位置。
- 記進帳本之後的每一條失敗都印「已計次」（先前只有分頁對不上的那一條印，SKILL 以它判斷算了沒）。
- 訊息裡「我們的分頁最後的網址」記的是確認的那個分頁本身的網址，不再依位置從清單取（清單位置有缺號時會取到旁邊的分頁）。

第三版：

- **記號**：落地網址後面加 `#akashic-` 加 16 個十六進位數字，每次執行不同。fragment 不送伺服器，HTTP 轉址會保留它。開分頁之後看幾眼，網址以記號結尾的那一個分頁就是我們的（兩個帶記號就停；在別的視窗就停，訊息請使用者關掉它）。不再讀 `is_current`，也不再比對開分頁前後的清單。
- **記號還在時**：每一眼以記號找分頁，位置與視窗編號跟著它走（左邊開關分頁、拖動、切換視窗都不停）；指令以記號鎖分頁（第四版起帶 `--profile`，見上）。導航到 PDF 連結時也帶著記號（連結本身有 fragment 時原樣導航、不加）。
- ~~記號只在轉址當中可以消失~~（第四版拿掉）：第三版在文章頁落定之後記號不見就停（結束碼 1）。
- **記號不在時**（Elsevier）：以視窗 id 找回視窗編號，以 `stillOurTab` 追蹤位置。顯示過網址的位置變成空白就算對不上（⌘W 接 ⌘T）。左邊開關分頁、拖動、我們的分頁被關、整份清單換了就停（結束碼 1）。
- **看不到就不動**：`documents` 讀不到就停；分頁不見了也停，不再當成「還沒落地」繼續等；四則整批暫停的訊息組字時不再讀分頁（讀失敗會把 6 變成 1）。
- **等連結**：切成 15 段、每段 3 秒，段與段之間確認；讀完連結也立刻確認一次。比先前一次等 45 秒慢：實跑一篇找不到連結的 SAGE，從開分頁到結束共 100 秒。
- **`fetch` 不關任何分頁**，結束碼 3、9 也留著。
- **`fulltext contract` 從 6 升到 7**（更正：第一版就升了，見第八版），SKILL 第 0 步一起升，錯誤訊息寫了建置 CLI 的指令（這個 CLI 沒有發布版）。#613 b47 留給使用者裁決的「只有印出的字改了要不要升」仍然沒有決定，這次升是因為行為變了。

## 量測（2026-11-04，使用者的 Safari，經同意）

每家開一篇 `https://doi.org/<DOI>#akashic-probe-<亂數>`，只讀 `documents --json --profile <P>`：

| 出版商 | 轉址之後記號 |
|---|---|
| SAGE、Wiley、Springer、APA、Taylor & Francis | 15 秒、40 秒都還在 |
| Elsevier | 1 秒在（linkinghub）；3 秒時在 id.elsevier.com 的授權轉址丟掉，之後的 ScienceDirect 文章頁沒有 |

doi.org 的第一跳六家都是 HTTP 302。ScienceDirect 在跟 PDF 連結之後的轉址（`pdfft` → pdf.sciencedirectassets.com）也丟掉記號。量的過程發現 `open --new-tab` 在多個視窗、Safari 不在前景時會開進別的視窗（三次，`--profile` 與 `--window N` 都會；safari-browser#351）；只留一個視窗時開對了。

## 擋不住的

- 使用者在 `fetch` 的分頁裡開別的網頁（⌘L）與分頁自己換頁分不出來，**任何出版商都一樣**（⌘L 本身就讓記號不見）：那一頁的網址、標題與文字會被讀來判斷（`testTypingInOurTabIsAKnownLimitForEveryPublisher` 釘住）。這是使用者 2026-11-04 接受的代價。
- 確認與導航一律是兩個 Apple event（記號在時也是：safari-browser 的 `openURL` 沒有網址重驗）；記號不在時確認與讀也是。分頁剛好在兩者之間移動，那一次讀或導航會打到別的分頁。位置鎖之下，兩者之間使用者點了自己的另一個視窗，也會打到那個視窗；別的 profile 的視窗開頭開著就不開始、執行當中才開的下一眼就停，但一眼與命令之間才開、又搶到同一個編號的視窗，那一次打得到。
- 顯示同一個網址的兩個分頁互換位置；兩個分頁群組剛好有一個相同的分頁時切換群組。
- 頁面的腳本看得到記號，分析腳本可能把它連同網址送出去；記號說明了這是工具開的分頁。
- 多個視窗時 `open --new-tab` 可能開進別的視窗（safari-browser#351）：`fetch` 會發現、不讀它，但那一頁已經載入了（第四版起，別的 profile 的視窗開著就在開分頁之前停）。
- 位置追蹤會保守地誤停：兩個分頁的視窗裡，使用者的另一個分頁剛好在我們的分頁轉址的同一眼換頁；分頁數在同一眼變了。停下不會讀錯分頁。
- `web-access.md` 的關分頁區塊（akashic-bootstrap、akashic-venue-works）有同一類競爭：safari-browser 的 `close` 不論用什麼旗標，都是切到那個分頁、再關視窗 N 目前的分頁。不在這次範圍內，另開 #769 追蹤（第二輪 verify 第 8 則）。

## 與 issue 寫法不同的地方

- 第三點（關分頁前比對請求的主機）：使用者 2026-11-04 選定不關分頁，這一點不再適用。safari-browser 修好 #348 之後也不能直接恢復：不關的主要理由是記號不在時認不準分頁，#348 不解這件事。
- 第一點對 `--resume-tab` 只在記號不在時不成立：接續帶了 `--resume-mark` 而分頁還帶著記號，就以記號認那個分頁；記號丟了（Elsevier）才照位置，這時接續讀、也會導航它沒有開的分頁，SKILL 要求接續前先確認那個位置。

## 第五版（第六版收回了前兩點與重跑導航，見下）

- **新分頁以 `--profile` 開**：safari-browser 有 #351 的修正時（`--version` ≥ `newTabPinnedSince`，現在設為 v2.8.1：#351 合併之後的第一個 release；版號不同就改這個常數；tag 之前的開發版算沒有修正），`open --new-tab --profile <P> --window <k>`，k 是我們的視窗在那個 profile 的視窗裡的順序（safari-browser 帶 `--profile` 時 `--window` 的意思）。這時不再因別的 profile 的視窗而停。沒有修正時照舊以全域的 `--window N` 開，並照舊停；**認不出 profile 的別的視窗也算**（第四輪第 6 則）。
- **位置鎖也帶 `--profile`**：`--profile <P> --window <k> --tab-in-window <T>`。確認與命令之間使用者點了別的視窗，全域編號會指到那個視窗（可能是別人的 profile）；profile 內的順序不會跨進別的 profile（第四輪第 5 則）。這在 2.7.0 起的 `js`、`wait`、`open`（導航）都能用，與 #351 無關。
- **記號鎖找不到分頁時重跑一次**：記號剛好在確認與命令之間不見（頁面用腳本換網址），或 `--profile` 一時對不上，再確認一次分頁、照確認到的鎖重跑一次；只重跑「沒有分頁符合」，命令自己的失敗不重跑（第四輪第 8 則）。失敗訊息印實際用的鎖。
- 導航之後的接續（`--resume-stage followed`）從一開始就算「已計次」，接續的兩個拒絕改走 `fail()`（第四輪第 4 則）；接續拒絕的分頁不是我們的，不印它的網址。
- ⌘L 的限制改寫成「任何出版商都一樣」（第四輪第 10 則），測試改名。
- linkinghub 插頁的 `left-site` 交接是 #768 之前就有的行為，測試把它釘住（第四輪第 6、33 則），不在這裡修。
- 契約 7 → 8：第三版印 7，導航時會開出新分頁，第 0 步要擋下它（第四輪第 36 則；印 7 的是第一到第四版，見第八版）。
- 過時的說明：`publishers.md`、`ToolRunner.swift` 的註解、規則檔、測試的註解。
- 這份 changelog 與原始碼註解不寫維護者自己的環境細節（第四輪第 26 則）。

**第五輪 verify**（2026-11-04）：FAIL，43 則，5 則 HIGH：重跑比對的是假瀏覽器自己編的字，真的 safari-browser 印 `No Safari document matches …`，所以重跑永遠不會發生；重跑真的發生時，導航只確認了分頁是誰就再送一次；版本閘靠一個猜的版號解除停止；safari-browser#351 的修正不能把新分頁釘在那個 profile 的視窗（我寫的第一個病因不對：視窗層級的解析回 `.windowIndex`，不是 `.resolvedTab`；更正貼在 #351）；記號在時的導航與 `--profile` 開新分頁都沒有實跑。另有 profile 內的視窗順序與 safari-browser 自己的算法對不上（沒有分頁的視窗、載入中標題空白）。

## 第六版（收窄）

## 第八版

- **PDF 連結的答案綁在判過的那一頁上**（HIGH）：`siteGuard` 只看主機，位置追蹤把同位置、同站的新網址當成我們的分頁在換頁，所以讀完連結之後分頁到了同站的登入或驗證頁，`fetch` 照樣拿舊頁面的連結導航，把那一頁蓋掉。現在記下 `botCheckPage` 判的網址，讀完連結與導航之前各比一次（我們的記號不算：頁面用腳本拿掉 fragment 不是換頁）。不同就判新的那一頁，登入、驗證頁照常 6／8；沒有訊號是結束碼 1（`the page changed after it was checked`），不導航，也不重讀連結。導航之前那一次是在記嘗試之後，所以 6／8 也印「已計次」。這個問題 main 上就有，不是這個分支造成的。
- **每一眼的別的 profile 檢查只看開頭沒有的視窗**（MEDIUM）：safari-browser 從視窗標題解析 profile，頁面載入中標題空白時讀不出來。先前同一個 profile 的第二個視窗載入新頁就會誤停，可能還在記了嘗試之後，訊息還說有視窗被打開。開頭檢查過的視窗以 id 記下；視窗的 profile 不會變。開頭沒有的視窗照舊：別的 profile 或讀不出來就停。
- **記號在沒有記號的一段之後回來，要在我們的位置上**（MEDIUM，第六輪第 6 則）：記號是位置鎖導航帶回來的，所以回來時要求它在我們的位置、而且位置追蹤成立。先前記號的分支不比對上一眼：導航的那一刻左邊開關分頁，`--tab-in-window T` 指到使用者的分頁，那個分頁被導航、帶著記號，就被當成我們的分頁、印 `handover`，真正的文章頁留在旁邊。現在停（結束碼 1，已計次）。使用者的分頁被導航這件事收不回，那是 SKILL 限制 (b)。
- 測試：導航之後接續（PDF 主機、沒有記號）在送出第一段腳本之前就因別的 profile 停（只有這條路上「停止排在 `resume` 之前」才有差）；`safari-browser --version` 回多新都不影響停止（版本閘回來時測試要紅）。
- 文件：契約 8 的歷史（印 7 的是第一到第四版，第五到第七版的開發建置也印 8 而行為不同，都沒有發布，不升版，CLI 從合併之後的 commit 建置）；SKILL 第 3 步的重跑範圍與限制 (b)；接續照位置的例外範圍；`plugin/CHANGELOG.md`；`web-access.md` 對這個命令鎖法的描述；「打不到別的 profile」改成照實寫。

**仍然擋不住的**（加在上面的清單之後）：網址不變而內容換了、或最後一次比對之後才換頁；沒有分頁的視窗（不在 `documents` 的清單裡，別的 profile 的檢查看不到它）；開分頁之後找記號的那幾眼與 `resume` 自己的那一眼不判別的 profile（那裡以視窗 id 認，開頭的檢查剛做過）。safari-browser 在錯誤之前多印一行時（daemon 退回、timing 紀錄），第一個非空行不是 `Error:` 那一行，讀取就不重跑：保守的方向，迴圈裡的讀取下一輪會恢復。

**第八版的 verify**（2026-11-05）：FAIL，28 則（反方沒跑完：網路錯誤）。第七輪的 HIGH 修好一半：不再拿舊頁面的連結導航，但一部分驗證頁成了結束碼 1。新的 HIGH 是 safari-browser#355。

## 第九版

- **分頁清單同一個位置兩列就停**（HIGH，第八輪第 1 則）：safari-browser 把分頁標題不跳脫地接進列舉（safari-browser#355，真實的 Safari 會不會保留那些字元還沒量），頁面可以寫出一列帶記號的假列，`ownTabNow` 就把它當成我們的分頁，導航打到別的分頁。假列刪不掉真的列，指向存在的分頁時通常與真的列同位置。以視窗編號與視窗 id 兩種認法比：safari-browser 以 id 解析分頁，編號亂寫的假列一樣打得到。根源的修法在 safari-browser。
- **換了頁之後判到底**（MEDIUM，第八輪第 5、8、10 則）：等新的那一頁落定（`watchOnSite`，與導航之前的接續同一套），再看訊號與驗證頁的網址。先前只讀一次、不看網址，還在載入的驗證頁與同站的 `/captcha/` 都成了結束碼 1。判過的那一頁本身也看網址：等連結時到了同站的 `/captcha/`、頁面沒寫出訊號，先前是結束碼 3，或記嘗試、導航。同站的 PDF 交給人，不再是結束碼 1。讀不到的頁面先前是 6，現在交給人（7 `unverifiable`）。
- **接續的兩個提早結束走 `fail()`**（MEDIUM，第八輪第 3 則）：`followed` 接續時視窗不見或 profile 不符，也印「已計次」。

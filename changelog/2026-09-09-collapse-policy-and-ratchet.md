# 收攏留存者政策，與受保護清單的棘輪（#468 #522）

兩張都是使用者交還拍板的裁決；兩個裁決都寫在程式碼與規則檔裡，不留在 issue。

## #468 —— 留哪一筆

收攏保首見，於是留下哪一側的判定原文與 `[rule: …]` 尾註由**排列**決定。

**政策三層，完全不依賴順序**：弱血統優先 → 平手取未被本次改寫的那一筆（keeper 側，與 #271 一致）
→ 仍平手取 statement 字典序最小。

**為什麼弱的勝**（issue 的三選一裡沒有這項，是讀它自己的原文浮出來的）：收攏只在兩筆對**同一個
配對**得出**同一個結論**時發生，差別只在理由。而 `rule` 尾註在下游的職責是**警告**
（`PersonResolver` 的「confirmed-elsewhere 弱血統可見」）。兩個方向都失真，代價不對稱：

| | 後果 |
|---|---|
| 留強丟弱 | 一個**確實存在的**弱血統警告被靜默拿掉。假陰性，而身分誤判不可逆 |
| 留弱丟強 | 多一句提醒給一個**正在做判斷的人**。假陽性，代價是一行字 |

前提是 `identity-is-judged-not-matched`：verdict 是判定，「丟哪一筆」等於「選擇保留哪個理由」。
第 3 層存在的唯一理由是殺掉陣列順序依賴——那正是 issue 的核心抱怨。

**誠實邊界**：收攏無論留哪一筆都會丟掉另一個理由，而 store 不留它。「合併兩個理由」不在選項內：
那要**編造**一個沒有人寫過的 statement。

規則名字面與 `[rule: …]` 尾註解析搬進 `AkashicCore`（`AkashicStoreIO` 讀不到 `AkashicEntity`）；
`ResolutionLedger` 的四個常數改成**引用**不是副本。

## #522 —— 刪除方向的棘輪

`missing` 問的是「清單裡列的路徑還在不在磁碟上」，而 **glob 產生的成員永遠不會「列了卻不存在」**
——它只會停止被列出。58 個成員裡 **37** 個是 glob／`swiftGuards()` 衍生的（顯式字面 21）。

三組實測，修前全部 rc=0 印「無缺口」，修後全部 rc=1 具名：

| 情形 | 修前 | 修後 |
|---|---|---|
| A 刪一整支守衛 | rc=0「無缺口」 | rc=1「少了 …」 |
| B 刪一條 glob 規則檔 | rc=0「無缺口」 | rc=1「少了 …」 |
| C 拿掉一條顯式 `DATA` 條目 | rc=0「無缺口」 | rc=1「少了 …」 |

**為什麼不是「把 glob 換成顯式清單」**：顯式今天 19/19 由 `missing` 具名，但換掉之後**忘記加新
規則檔是靜默的**——同一個失效換一步，而規則檔正是本 repo 承載裁決的地方。

**它不是 #518 記過的「第 N 份副本」**：那次的缺陷是複製清單與 `DATA` 之間**沒有東西在對帳**；
棘輪整個存在理由就是被對帳。同形先例是 `hash-table-drift.sh`。清單來自**同一個**
`protectedInventory()`——一個自己算一遍的棘輪只會證明它自己與自己一致。

### Expected 2：`PATH_ROOTS` 不再是手維護白名單

它**漏過兩次**（`mcpb/` 是這道檢查上線第一次執行才補的；#518 R1 又發現漏著六個）。「一份手維護
的白名單會漏」正是這整支守衛在講的事——把它自己也交給機器算。放寬後零新缺口。

### Expected 3：量測翻掉了它自己的前提

它提的是「`READS` 的鍵從 basename 換成完整相對路徑」。**那不解決 phantom reader**：`DATA` 裡寫的
本來就是完整路徑，換過去照樣命中。真正的來源是**「持有清單的檔案自己是一支守衛」**——清單搬進
一個沒有 `main.swift` case 的檔之後，phantom 結構上消失：**實測 22 → 2**。

另量：`READS` 的邊裡完整路徑命中 64 條、只靠 basename 17 條。收窄會拿掉那 17 條，而多餘的邊只
產生多餘的**紅**、少掉的邊產生**綠**——收窄的失敗方向比放寬糟。所以 basename 回退保留。

### 一則量測方法上的更正

第一次量 C 時：在副本裡改原始碼然後執行 binary——而守衛跑的是**已編譯的 binary**，改原始碼對它
無效。那一格量到的是「原始碼被改而 binary 沒重編」。與本 issue 半二第六種寫法（`*Data.swift` 不在
掃描範圍）同一個根：**掃的東西與跑的東西不是同一份。**

`zero-instance-guards` 第 21 列。理由與既有 20 列都不同：前二十列的零是「**還沒有**這個守衛」，
這一列的守衛在、天天跑，只是**它的謂詞對那一類成員結構上不可能為真**——不是漏看，是問了一個
glob 成員答不錯的問題。

PR #536。

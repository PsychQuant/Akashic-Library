# trigger-coverage 的已知缺口清單（#690）。守衛：`akashic-guards trigger-coverage`。
#
# 管的是一種缺口：守衛宣告讀的範圍（`// trigger-coverage: reads <樣式>`）裡有不在受保護集合的檔，
# 而那些檔改動時沒有任何 CI workflow 跑這支守衛。
#
# 一行一條，四欄以 TAB 分隔：<守衛的 repo 相對路徑> <它宣告的樣式> #<追蹤的 issue 號> <缺口大小>
# 例：Sources/akashic-guards/NetworkConfinement.swift<TAB>Sources/*/*.swift<TAB>#690<TAB>115
# issue 號不以 0 開頭、至多 7 位（#710）：`#0`、`#0000` 這類占位是格式不對。只驗形狀，不查 issue 存不存在。
# 缺口大小（#711）：被接受那一刻「CI 未覆蓋」的檔數，正整數、不以 0 開頭、至多 7 位。量法：跑
# `.build/debug/akashic-guards trigger-coverage`，宣告範圍那一行印 `CI 未覆蓋 N 個`，取 N（不是前面的「不在受保護集合 M 個」）。
# 以 # 開頭的行與空行略過。
#
# 列在這裡的缺口照樣印出來（⊘），不計入 rc。列了、但缺口已經不在（例如 workflow 的 paths 補上了）→ 守衛失敗，
# 要人把那一行拿掉，否則豁免會變成沒人記得的放行。格式不對的行 → 守衛失敗，不靜默略過；只有三欄的舊格式也是格式不對。
# 現在的「CI 未覆蓋」檔數超過記錄的缺口大小（那一片範圍長了新檔）→ 守衛失敗：issue 接受的是那個大小的缺口，不是任意大小。
# 處置：確認新檔也可以不跑那支守衛之後，把第四欄改成現在的數，並回該 issue 記一筆；縮小照樣是綠的，⊘ 行會建議把第四欄改小。
# 同一個守衛、同一個樣式列兩次算格式不對；對不到任何宣告的條目（守衛檔不在、樣式不逐字相同）也是守衛失敗。
# 樣式要與守衛那一行 `trigger-coverage: reads` 的樣式逐字相同。CRLF 行尾可以。
#
# 第四欄的三個限制（#711 R1 verify）：
#   · 它是淨數：同一片範圍刪一個檔、加一個檔，數不變、守衛不出聲。要擋替換得記檔名，這裡沒做。
#   · 「CI 未覆蓋」數的是磁碟上的檔（不是 `git ls-files`）：工作樹裡一個未追蹤的暫存 .swift 就會讓本機 pre-push 轉紅、
#     訊息叫你把第四欄改大。改之前先 `git status --short Sources` 確認多出來的都是追蹤中的檔；是暫存檔就刪掉它，不要改第四欄。
#   · 只驗形狀：記一個比實際還大的數，等於讓缺口長到那個數之前都不出聲。記量到的那個數，不要往上取整。
#

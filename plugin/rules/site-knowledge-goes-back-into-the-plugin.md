# 量到的站別做法要回到 plugin——不留在對話、暫存腳本或個人記憶裡

適用於本 plugin **每一個讀外部網頁或 web API 的 skill**（使用者 2026-11-20：範圍是所有碰網站的 skill，不只取全文）。

不適用於不碰網站的工作（只讀寫 store 的 skill 步驟），也不適用於「這一筆資料查到什麼」——那是 store 的內容，照 [`source-of-truth-over-consent`](source-of-truth-over-consent.md) 寫進 store，不是這條規則管的事。

## 規則

### 1. 什麼算要寫回的更新（封閉列舉，只有這三類，不得依性質相似類推第四類）

| # | 類別 | 例子（2026-11-20 那一批） |
|---|---|---|
| 1 | 某個站量到了 plugin 還沒有紀錄的行為：哪個連結通到哪裡、工具的結束碼與交接原因、按了之後檔案落在哪裡、沒有權限時頁面上的字 | Cambridge Core 上的 Psychometrika：PDF 連結導航之後分頁不離開摘要頁，頁面寫「Get access」「Add article to cart」 |
| 2 | 量到的與 plugin 寫的不同 | Wiley 的 epdf 閱讀器：文字寫 `snapshot -i` 讀不到任何下載鈕，那一篇讀得到 |
| 3 | 流程照字面做不到，或照字面做會得到流程自己沒料到的結果 | 視窗裡出現顯示 PDF 的分頁之後，對話框探測把整個視窗讀成 `unknown`，後面每一下「按之前先看對話框」都會停 |

你自己漏做一步（文字有寫、執行時沒照做）不屬於這三類：那一批的回報照實寫漏了什麼，不改 plugin。

### 2. 什麼時候寫

**一批做完、向使用者回報之前**（使用者 2026-11-20）。回報裡列出寫了什麼：哪個檔、加了或改了哪一列。批次中途不停下來改檔。

### 3. 寫到哪裡（封閉列舉）

| 量到的是 | 寫進 |
|---|---|
| 出版商或網站的行為，由 `akashic-fetch-fulltext` 量到 | `skills/akashic-fetch-fulltext/references/publishers.md`：依日期開一節，一站一列 |
| Safari 或 safari-browser 本身的行為（分頁開在哪裡、對話框與面板讀起來是什麼） | `skills/akashic-fetch-fulltext/references/safari-measurements.md`；同時在 safari-browser 的 repo 查有沒有既有的 issue，有就補實測，沒有就照下面第 4 條的 (b) 處理 |
| 期刊網站的行為，由 `akashic-venue-works` 量到 | `skills/akashic-venue-works/references/site-access.md` |
| web API 或名冊、個人頁的行為，由其他經 `web-access.md` 取得的 skill 量到 | `skills/akashic-bootstrap/references/` 下講那個來源的檔（作品來源在 `work-sources.md`，人的來源在 `person-sources.md`，Semantic Scholar 在 `semantic-scholar.md`）；取得程序本身的行為寫進 `web-access.md` |

表裡沒有的組合，先在這張表加一列再寫，不要挑一個看起來相近的檔。

**與 `SKILL.md` 的句子不同時，同一個變更裡改那一句**，並寫明是哪一天的哪一次量測。舊的列與舊的句子加註、不刪：它們是當時量到的事實，被推翻的是「現在仍然如此」。

**會改變流程怎麼判的句子不在這條規則的授權內。** 量到的事實讓某條處置規則顯得不對時（例如第 1 條第 3 類的例子），寫下事實、指出它碰到哪一條，處置規則本身怎麼改交給使用者裁決。

### 4. 誰來寫（封閉列舉，依這個工作階段手上有什麼）

| # | 情況 | 做法 |
|---|---|---|
| (a) | 這個工作階段讀得到 plugin 的原始碼 repo，而且使用者是它的維護者 | 在 repo 的功能分支上改檔、commit。推送、開 PR、合併各自照使用者自己的確認規則；本規則不授權其中任何一步 |
| (b) | 其他（一般安裝：只有 Claude Code 管理的 plugin 安裝目錄，不改它） | 把同樣的內容寫成回報裡的一節「要寫回 plugin 的觀察」，照第 5 條的欄位寫；問使用者要不要把它送到 plugin 的 repo（開 issue 是把內容送出這台機器，由使用者決定，內文先過隱私檢查） |

### 5. 怎麼寫：證據範圍

每一列帶：日期、主機（學會或子刊的子網域照實寫，不寫成母站）、幾篇、工具的結果（結束碼、交接原因）、之後做了什麼與看到什麼、環境（safari-browser 版本、`akashic fulltext contract` 的值）。

- 量到一篇就寫一篇，不寫成「這一站都這樣」。
- 原因是推論、或來自使用者的說明時，照實標明，並寫出沒有做的對照。
- 權限因機構而異：「取得成功」「沒有權限」都只代表那個網路、那一天。

每一句都是關於世界的斷言，寫之前照 [`assertions-must-be-measured`](assertions-must-be-measured.md) 的四個問題過一次。

### 6. 寫進 repo 之後，要到達實際在用的版本（只適用第 4 條的 (a)）

取得方式的改動合併進預設分支之後，**同一個工作階段**把這台機器上安裝的 plugin 與 `akashic` CLI 更新到合併後的版本，並確認：plugin 的版本號、`akashic fulltext contract` 印的值，都是合併後的。

- 合併與更新安裝的版本，各自要使用者確認；這一條規定的是「不要停在合併之前就當成做完」，不是讓它們自動發生。
- 沒有更新完就結束時，回報寫明安裝的還是哪一版、差在哪幾項。
- skill 的版本檢查擋下舊的 CLI 時，處置是更新 CLI；不請使用者配合舊版才有的限制。

## 為什麼（2026-11-20，同一天、同一個工作階段的兩種落差）

**安裝的版本落後。** 安裝的 CLI 印 `fulltext-contract 10`，而「別的 profile 的視窗開著就停」這個限制在分支上已經依使用者前一天的裁決拿掉。舊的 `fetch` 仍然停下，Claude 因此請使用者去關視窗；使用者指出那個限制早就拿掉了，之後才合併、更新。第 6 條防的是這個。

**量到的沒有寫回去。** 更新之後在真的出版商網站上抓九篇全文，量到的事有三件與 plugin 的文字不同或 plugin 沒有（第 1 條表裡的三個例子），另外四個站的結果是 plugin 第一次有導航之後的實測。這些原本只在那個工作階段的對話與暫存腳本裡。使用者當場說：

> 「akashic 的plugin要有一個rule是每次更新pdf取用方式都要更新到plugin上」

問他要的是「寫回檔案」還是「發布到安裝的版本」時，他選了兩者都要；範圍選了所有碰網站的 skill；時間點選了整批結束、回報之前（PsychQuant/Akashic-Library#822）。

**不寫回去的代價是下一次照舊的文字做。** 站別紀錄寫得比實際保守，能取得的全文會被列成「取不到」或多交給使用者一次；寫得比實際寬鬆，Claude 會照過時的步驟對網站動作。兩種都不會報錯。

## 這條規則做不到的事

- 它不讓規則自己被讀到：`plugin/rules/` 不自動載入，要靠各 skill 在回報那一步引用它（`akashic-fetch-fulltext` 第 7 步、`web-access.md`〈其他〉）。沒有引用到的 skill 不會照做。
- 第 4 條的 (b) 只做到把觀察交到使用者手上；他不送出，plugin 就不會知道。
- 沒有檢查會發現「量到了卻沒寫」。

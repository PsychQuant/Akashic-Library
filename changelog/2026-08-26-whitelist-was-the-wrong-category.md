# 換一個白名單不是修好，是把邊界挪了一格

2026-08-26 凌晨。第四輪 verify（`wf_2350c49a-f58`）在**第三輪的 6 條修復裡**找到
5 個 HIGH——連續第四輪（52 → 5 → 6 → 5）。本篇修其中兩條。

## 我修的東西，和它原本的病，是同一個範疇

| 輪次 | 判準 | 形狀 |
|---|---|---|
| 原缺陷 | `hasPrefix("value:")` | 白名單 |
| R3 修法 | `looksLikeYAMLMapping`（首字元字母、到冒號只有 `[A-Za-z0-9_.-]`） | **仍是白名單** |
| R4 修法 | **`ISSN(v) != nil`** | 問一個性質 |

R4 實測四種**合法的** format-13 元素落在 R3 新邊界的外面：

```
- value : 0003-066X                      冒號前一個空格
-  value: 0003-066X                      兩個空格
- {value: 0003-066X, qualifier: print}   flow mapping
- "value": 0003-066X                     引號鍵
```

而前兩者改寫後產生 `- value: value : 0003-066X`——**整檔 YAML ScannerError**
（plain scalar 不得含 `: `）。**比原缺陷嚴重**：原缺陷只是 decode 失敗，這是語法錯誤。

**最刺的一點**：R3 的註解**寫出了正確的性質**——「ISSN 與 ISBN 的值**不含冒號**，
所以『含 `<鍵>:`』與『是裸的識別碼』互斥」——然後實作了它的**近似補集**。
正確判準一直就在那句話裡，我只是沒有直接用它。

## 新判準：不確定就不碰

```swift
static func isBareIdentifier(_ v: String, field: String) -> Bool {
    switch field {
    case "issn": return ISSN(v) != nil
    case "isbn": return ISBN(v) != nil
    default:     return false
    }
}
```

由**型別自己的建構器**回答，不由形狀猜。於是它只在「確定是裸識別碼」時改寫——
mapping、垃圾、解析不出的值一律不動。

**連 `- 12345` 也不碰**：把它包成 `- value: 12345` 只是把 decode 失敗換個位置，
而且假裝我們認得它。不確定就交給 quarantine 具名，那比猜一個包裝誠實。

## 序列的邊界也從白名單改成性質

R3 的續行判準是「首字元是空白且非空」——於是序列中的**空行**與 `#` 註解會把
`inList` 關掉，其後的裸純量全部漏掉（R4 ⑤）。

新的邊界是**下一個頂層鍵**（第 0 欄的 `<鍵>:`）。那才是序列真正結束的地方；
空行與註解仍在序列內。

## 訊息：從「假的全稱否定」改回「若是…」

R3 我把「那**可能**是沒認出的寫法」改成「這裡**不會**是裸純量序列……所以是別的原因」。
R4 指出同一個 `guard` 內**往上 15 行**的註解就列著四種反例，兩句話互相否定。

而即使有了新判準，那句全稱否定**依然是假的**——CRLF 行尾、縮排序列、未被 git 追蹤的檔
都仍會漏。新訊息改回條件式，並**具名那三種已知會漏的形狀**。

**斷言一個全稱否定，需要的證據比斷言一個可能性多得多**——而我當時是為了「更正」上一版
才寫成否定的。修一個過強的斷言時，很容易寫出方向相反、同樣過強的另一個。

## 純函式化

`upgradedLines(_:)` 抽成純函式（`[String] → [String]`），於是那五種形狀可以**逐一單測**
而不必造 store、commit、跑遷移。R3 的測試要走完整條 `run()` 才驗得到一種形狀——
那是為什麼 R3 只測到兩種。

## 二、刻意的行為改變（整合者貼到 #629）

「移植 issue 的 Impact」寫的是「不改變使用者可見的行為」。下面這些是**知道地改變**的，每條都有理由；請使用者對標 ★ 的確認或翻案。

### 取得與編排
1. ★ **`crossref-match` 是重播協定，不再是「一個指令跑完整批」**：舊腳本自己連 Crossref（`--delay 0.5`）；新版每輪把缺的請求列成 JSON、exit 3，由 agent 逐筆用 safari-browser 取回、存檔、重跑；每筆作品最多四個請求（一般查詢→剝審稿後綴→限定 journal-article 重查→反向驗證）。這是為了守 `web-access-via-safari-browser`（`Sources/` 沒有 HTTP client）的**有意取捨**，但操作規模是退步：changelog 的對照語料 62 筆 × 30 個種子在這個協定下就是數千次經瀏覽器的取得；搜尋類請求沒有單一 id 可核對（work-sources.md 要 agent 自己 `cmp -s`）。**請使用者確認可以接受，或另定批次上限。**
2. `crossref-match` 的契約差異：`--delay` 移除；`--mailto` 進請求網址（不進 User-Agent）；回應的 DOI 與請求不符 → `IdentityMismatch`；候選 DOI 形狀不合 → `UnsafeDOI`（舊：百分比編碼後照送）；查詢端點回 404 **或形狀不對（R1 起：`message` 不是物件、`items` 不是陣列、任一缺席）** → exit 1 具名中止；`-o` 現在共用 `AbstractProposals.writeOut`：拒絕寫到既有的 symlink／目錄、`mkstemps`＋`rename` 原子替換、檔案權限 `0600`（舊：`open(out, "w")`，依 umask 通常 0644）。
3. ★ **`fulltext calibrate` 不再連網，形狀改了**：讀 `--crossref` 目錄（每個檔是一個 Crossref 回應，以 `message.DOI` 對回 PDF）；缺記錄時列出（DOI＋完整網址）並 exit 3，`--partial` 才照量；一個檔案都沒量到 exit 4（R1 起）；DOI 形狀不合格的不組網址。「重跑那組 22/28、0/808」比舊版多一段人工取得。
4. **`akashic fulltext` 的用法錯誤結束碼**：`fetch` 缺必填旗標／未知旗標 1→64；`verify` 缺 `--title` 2→64；`url-rule` 缺引數 2→64；`jitter` 參數不合 1→64（ArgumentParser 的用法錯誤是 64）。SKILL.md 先前只寫了 `fetch` 的差異；plugin/CHANGELOG 已補。`FETCH_FULLTEXT_NAP` 環境變數移除。
5. **`fetch` 的新不變量（R1，程式強制）**：`--landing`／`--prime` 只收 `https://`；頁面 DOM 給的 PDF 連結 origin 必須與頁面相同（否則結束碼 1、分頁留著，不發 `credentials:'include'` 的 fetch；出版商規則產生的網址不受限）；`--expect-profile` 命令列必填（原本只是文件叮嚀）；三個輸出目的地不得是目錄／symlink／特殊檔；覆寫是原子替換；暫存目錄 0700；poppler 逾時 120 秒；base64 容忍換行；`--title`／`--pages`／`--doi` 可以以連字號開頭。
6. **git 閘 fail-closed**：輸出目錄的祖先有 `.git` 時，git 執行不起來（`/usr/bin/git` 不在）、`rev-parse` 非零（`.git` 指向不存在的 gitdir、`safe.directory` 的 dubious ownership 回 128、`.git` 壞了）、`rev-parse` 不是 `true`、`check-ignore` 不是 0／1，一律拒絕並說原因。祖先都沒有 `.git`＝不在任何 repo 裡，不需要 git 回答，直接放行。git 走 `/usr/bin/git` 絕對路徑（PATH 上的 shim 不能作答）、剝 `GIT_*`、`-c core.fsmonitor=false`、`-c core.attributesFile=/dev/null`。**舊 shell 的語意在這裡是 fail-open（同形狀），所以這不是回歸，是這一輪多關的一道。**
7. ★ **`abstracts-to-proposals` 的 store 解析走 CLI 全鏈**（`--library` → `$AKASHIC_LIBRARY` → registry 的 `current`）：舊腳本刻意只有三段（`--library` → `$AKASHIC_LIBRARY` → `~/.akashic`），是 #519 Expected 3 的明文裁決（「明寫限制而不是接上去」）。移植成 `akashic` 子命令之後它與其他命令同一條，那個限制連同理由一起消失——但這是**推翻一條被記錄的裁決**，不是純移植。SKILL.md 與 plugin/CHANGELOG 都有寫。skip 報告的控制字元逃脫格式從 `\x1b` 變成 `\u{001B}`。
8. **JSON 語意**：舊腳本用 `json.loads`；第一版移植用 `JSONSerialization`，重複鍵取第一個、吃掉字串內開頭的 U+FEFF、接受尾隨逗號、拒絕 NaN。R1 起用 `PyJSONParser`（`json.loads` 的文法），四處與 Python 一致。**與 Python 仍有的差異**：巢狀深度上限 512（Python 的 C 掃描器接受更深）、孤立的代理對拒絕（Python 接受並產生孤立字元）、超出 `Int` 的整數退成 `Double`。
9. **Unicode**：`PyText.nfkc` 改為 NFC(NFKD(s))（Foundation 的一步 NFKC 對相容分解後的組合序列與 Python 不同）；bot-signals 把 U+0130／U+0131 折成 `i`（Python 的 `re.I` 這樣看）、`\b` 換成明寫的字元類。**已知仍有**：新指派碼位取決於執行環境的 Unicode 版本；`HTMLEntities` 只實作用得到的子集（XMP 是 XML，只有 5 個合法實體）。

### 守衛與普查
10. **`literal-census`**：預設 store 由 `--library`／`$AKASHIC_LIBRARY`／registry 解析（舊：`~/.akashic`）；`AKASHIC_BIN`／`AKASHIC_REPO` 不再有作用；記錄檔讀不進來 → 具名 exit 3（舊：traceback）；R1 起列不出來的目錄同樣 exit 3。
11. **`scan-yaml-profile`**：位置引數＋預設 `./library` → `--library`＋registry；parser 層由 PyYAML 換成 libyaml event 流（讀端用的那個；對「什麼算 parse 失敗」偶有不同，實測 `a:\t1`）；`--inspect` 輸出順序不同；R1 起：根不是資料夾／讀不到的檔／零個 `.yaml` 都具名失敗（exit 1／1／3），路徑縮成 `~`，alias 事件算 anchor（與 PyYAML 同）；型別改 `package` 存取層級。
